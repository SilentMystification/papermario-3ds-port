# Row AUDIT: read-only sanity check of the whole 3DS runtime (one Opus agent)

## User goal (2026-11-08)
"The big goal is that all the game systems communicate and collaborate effectively and efficiently." Also: well designed, no duplicate or convoluted work; areas to optimize for 3DS hardware; no code that looks like low-quality AI-generated code; professional and sensible design; audit the fp24/fp32 math so that no seams come from it.

## 0. First check (scope is current)
git log --oneline -1; `ls 3ds/src/*.c 3ds/shaders/*.pica | wc -l` (expect 57 + 3); `test ! -e 3ds/src/pm_gbi.c`; `grep -rln TARGET_3DS src | wc -l` (expect 49). Any difference: rebuild the scope map from ls first.

## 1. Scope
Read: all 3ds/src nd_*.c and pm_*.c, 3ds/include, 3ds/shaders/pm.v.pica, pm4.v.pica, pm5.v.pica, 3ds/ld/3dsx.ld.in, the TARGET_3DS blocks in src/ (producer records, model.c, sprite.c, effects hooks), CMake flags, gen_map_restore.py output shape. Skip: decomp game logic outside TARGET_3DS blocks; audio DSP internals (pm_dspaud.c, pm_vadpcm.h) unless a lock or allocation finding leads there; 3ds/src/map_restore_table.c; docs except hw_guidelines.md and INDEX.md.

## 2. Axes (in this order)
A0. System interfaces (the frame of the report). Map each interface: game loop and frame pacing; display-list producer -> walker (nd_walk) -> geometry/ring (nd_geom, gtrip/gappend) -> batch close -> GPU submit (nd_raw_native, nd_emit, citro3d); texture cache (load -> slot -> stage -> upload -> bind); audio; input; menu/options; logging (game thread, log writer thread, sink thread); file I/O and map load/restore; memory allocators (linear, VRAM, heap). For each interface: owner of the data, copies or passes that cross it, call frequency (per frame / per op / per vertex), locks or waits across threads, state that two systems keep for one fact, order dependencies inside one frame.
A1. Duplicate, dead and parallel paths: one job in two functions (uv formula in nd_geom.c, nd_comb.c t1_fold_tri, nd_rect.c, nd_model gv params; clip-bit helpers; "seen"/"log once" statics); symbols never called (nm of the elf vs the map); debug switches no open row names (PMDL("..."), pm_debug_has("...") vs docs/handoff/row_*.md); CPU-path names left in code and comments (flush_draw_cpu, pm_gbi.c, draw_tri_cpu); pm.v.pica (DVLE 0) still bound or not.
A2. Convoluted control flow: flags whose meaning changed (combine 1-8 legacy vs plan, rect_c[4] "cpu" now drops, nraw_why slots never set); globals written by several modules (GLOB writer list); functions over ~150 lines (flush_draw, nd_raw_native, rec_run, nd_walk_run, pm_tex load paths); switch-driven branches in hot functions.
A3. AI-smell patterns, each with file:line: row-code comments ("S3N-7:", "FB-2:") instead of why; checks that cannot fire; unnamed magic numbers (0x210, 7680, 26811, 0.012f, 127.f, 4096/1024/256); copy-paste near-duplicates (pm4/pm5 upload blocks, rect pieces); mixed naming (pm_ vs nd_ in one layer), unused parameters, `(void)x` noise, dead `#if 0`.
A4. 3DS hardware fit (hw_guidelines.md): hot span resolves in the map and stays under 16 KB; L1D footprint of hot tables (gm_tab, pcomp, mc_pool scans, scm memo linear scan, tmpl lookup); division, double, sqrt, int/float round trips per vertex or per op (nd_geom.c, nd_rect.c, nd_comb.c, nd_model*.c, gtrip/gappend, pm_tex decode); cache flushes per frame (GSPGPU_FlushDataCache, pm_fl_dc); GX queue use (pm_gx_room, pm_gx_drain, copy_guard); linear vs VRAM placement; per-frame malloc/linearAlloc; lock hold time (con_lock, fb_lock, queue lock).
A5. Data flow cost: per draw, how many times each vertex and state word is copied or hashed (TevKey, NdTmplKey, ndmc key, scm sig, sc_sig); texture path copies; pm_log_* cost when off.
A6. fp24/fp32 and seams: trace float32 -> PICA fp24 (16-bit mantissa): uniforms (C3D_FVUnifSet), vertex attributes (16-byte Vtx shorts/bytes with attribute scale; rect shorts s*sc in tex_raw_piece), pal/pcomp matrices (composition order in pcomp_calc, projection with depth folded in, RECT_GM), zmix/depth map, decal bias, clip and viewport (vp_sx/vp_tx, 40-pixel offset, wide 1.25 scale), uvso/uvx (t1_fold, t1_fold_tri, dual_bind ratios), nd_rect.c texrect s/t (1/32 and shift_mul, inclusive corners), fold_axis (+0.5f), near plane and w (GP2 user clip, w <= 0.05). Flag every place where two paths draw neighbouring geometry with different math (rect pieces of 120 texels, integer edges ia/ib vs float s; map shapes vs native model draws of one mesh; native sprite next to walker triangles; a half-texel offset on one path only (H06b1); sc 4096/1024/256 quantization per batch). Class each risk edge (position) or texel (uv) and name the differing value.

## 3. Method
grep and read only; line ranges for files over 400 lines. Each finding: file:line, the code, the value or count that proves it. No finding without a code line. No source edits. Azahar: at most 2 starts, only to confirm one number, with a bench and a status line in 3ds/logs/perf/status_AUDIT.txt (CLAUDE.md rule 5). No console runs (a console measurement is a request to the user).

At most 300 lines, 40 findings, top 10 with full evidence.
