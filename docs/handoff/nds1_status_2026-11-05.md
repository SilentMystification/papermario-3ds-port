## What works (gated)
- Tests before code: draw census logger, host tests (nat_host_test.sh, ndt_host_test.sh, tex_conv_test.sh), shot scenarios (mac01t, census_toad_shot), region_diff.py.

## What failed (valid gate)
- E5-3 (emit learned map groups through nat_emit): census_mac01 71 batches against 64. Cause (diag_e53_batches.md): the replay issues one draw entry per learned batch (14 batches for a group the live path draws as 7), because the live path merges adjacent batches (grange merge) and the replay does not. Learn windows add 0 batches. The patch is docs/handoff/nds1_e53_wip.patch (not applied).

## Findings that change the plan
1. Geometry replay is already done: DLC2 static groups copy Vtx once and replay index lists (pm_dlc.inc.c). The remaining per-model costs are the texture state (38 percent) and the batch close (23 percent).
2. Record replay (UC3e) saved nothing in Azahar and Azahar has no cache model, so only the console can show a gain. No console measurement of any replay build exists.
3. Replaying recorded batches doubles draw entries where the live path merges. A native path must emit MERGED ranges (one entry per grange), not per learned batch.

## Recommendation (needs the user)
Push a build to the console and measure fsplit gbi/dl with the current native HEAD (no nds1) first, then decide. Two routes after that:
- A: finish E5-3 with merged-range emit (store grange state per learned group; map_e4.md section on grange state). Larger.
- B: skip replay. Cut the per-batch cost inside flush_draw (texture bind chain, TevKey compare, the five uniform memcmps) with a prebuilt per-template state block applied only when the template changes. Smaller, the 61 percent of the cost that remains, and no new draw path.
Route B is what the plan's cost split (texture 38 percent, batch close 23 percent) points at.
