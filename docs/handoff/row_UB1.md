## Oracle review mac_00 layout-dependent sky row (2026-11-07; row MAC00 continues)
Plain 55a41fa6b^ and 55a41fa6b are byte-equal; with FB-2 e954bc9d1 applied to both, row 58 (framebuffer column 181) differs, and the FB-1 ring build moves other rows: a layout-sensitive effect. Only undefined behaviour can do that: an uninitialised read, an out-of-bounds read, or an address-derived value.
Candidates: 1 (top) an input of the sky texrect or its tile read from uninitialised or out-of-bounds memory, moving the seam between the two bg_sky_rows rects by one row: src/background.c 3DS path (bg_sky_rows, gBackroundTextureYOffset, backgroundMaxY); nd_rect.c 61-108 t0 = ((s16)(hs & 0xffff) / 32 * mt - tile_y0 - tile_fy) / th, ry0 = (yl + 3) >> 2, ry1 = yh >> 2 from the walker words and nd_ws.tile_y0, tile_fy, tst1.tile_sz/shift. 2 the sky decode (296-wide CI8 into the 512x256 slot, pm_tex) reads past its source or uses a wrong stride for the last or wrapped row. 3 the SIZE-3b uninit leads (not expected here).
Measurement (builds 55a41fa6b^ and 55a41fa6b, cold det, frame 200, one log): per sky texrect raw xl, yl, xh, yh, hs, hd, tile_x0, tile_y0, tile_fx, tile_fy, tile_sz[rtile][0..3], shifts, rtile, computed s0, t0, s1, t1, rx0, ry0, rx1, ry1; plus background.c y0, h, bgMaxX at the call. Inputs differ: the first differing field names the garbage producer (fix its writer). Inputs equal: dump slot rows y0+57..y0+59 of the decoded sky in both builds (cause 2). In parallel: build with -ftrivial-auto-var-init=pattern for src/background.c, nd_rect.c, pm_gpu.c, pm_tex.c, then the whole game TU; a deterministic sky change confirms an uninitialised local; bisect by file group; add -Wmaybe-uninitialized there.
Fix: initialise the named field or local at its definition, or bound the read. -ftrivial-auto-var-init stays a diagnostic, not the fix.
Gate: spot_mac00_det_pic byte-equal across 55a41fa6b^, 55a41fa6b and nds1 head (cold det); the pattern build gives the same sky; mac_01 and nok11_det unchanged.

## Oracle review MAC00 (address-dependent slot reuse, 2026-11-07)
A code-size change moves .data/.bss addresses. pm_tex picks the victim slot by stamp/LRU with ties and probing in hash order of the image address (slot hash, addr_h); linked image addresses move with the layout, so the victim changes. Ranked: 1. a slot reused inside the frame that still samples it: a native bind path (pm_tex_native_unit0/1, nd_tex_unit_hint on the model hit path, the snapshot copy) fetches unit words without refreshing the slot's in-frame use mark, the slot is evicted and its VRAM slab overwritten by a later upload in the same frame; the GPU runs the earlier draw later and samples overwritten bytes (row 58 plus blobs). FB-2 added slab and copy traffic. 2. a native bind of a slot whose VRAM upload is still pending (the vram_up staging race FX1 saw). Ruled out: model cache key addresses, gm_tab malloc order, qsort, timing under det.
Measurement (no log in the draw path): two cold counters in pm_tex.c, increments only, printed once at f300 in the frame-end prof line: reuse_inframe (a slot evicted or reused while its last bind, any path, is in the current frame) and bind_pending (a native unit fetch of a slot whose upload is pending); plus the image address and slot index of the first event. Run the 235 px build (599c48970+e954) and the 0 px build (same plus the 256-byte rodata control).
Fix: (a) every native fetch stamps the slot used-this-frame; eviction never picks a slot used in the current frame (take an older one; if none, split the frame and recycle at the next frame begin, as the FB-1 chunk rule). (b) a native bind of a pending slot forces that slot's upload before the draw, or binds the staged copy until the upload ran.
Gate: spot_mac00_det_pic byte-equal across 55a41fa6b^ and 55a41fa6b with FB-2, the pattern-init builds and the rodata-control build; both counters 0 in all; mac_01, nok11_det, iwa_10 unchanged.

## UB audit result (2026-11-07, read-only agent, nds1 c2dba5cc2) and row UB1
Map (lane-mac00): pm_tex.o .bss 0x01218ef0-0x012433c4; growing it shifts every .bss object up to pm_map.o last_asset_src (0x0143ee2c); gMapShapeData, gBackgroundImage, nuGfxZBuffer and later do not move. So the bad access's target lies in [0x01218ef0, 0x0143f000): pm_tex, pm_gbi (box_buf, vert_*), nd_mtx*, nd_core, nd_tmpl, nd_tex, nd_comb, nd_cen, nd_shape, nd_ent, nd_dlc, nd_model (rng, mc_*, nat, hd_*), pm_os, pm_audio. Every index into the pm_tex.c statics is bounded.
Ranked suspects:
1. (top; fits the FB-2 dependence) stale unit 1/2 words replayed from the model cache: nd_model.c:348 stores d->u[1] = *c->u1 (and uvx, unit 2) in mc_pool; pm_gpu_model_hit (pm_gpu.c:3637-3651) refreshes only u[0]. The key (ndmc_cmp words 0-32, 38, 53, 54) holds no unit-1 slot or slot generation. If the aux slot was staged at store time, u[1].addr is the linear vram_stage copy, freed 2 frames later (pm_tex.c:1079-1083, pf_add); a later hit samples freed linear memory whose content depends on allocation history.
2. range merge (nd_model.c:499) compares only the template id and index contiguity; it ignores the per-range gv (uvso, cmul, cadd, zmix, fx5 from pm_gbi_gv_at), the unit words and use5.
3. template register delta (nd_emit.c:47-53 skips equal words) after C3Di_UpdateContext (pm_gpu.c:1196) can leave citro3d's value in place; the shadow resets only on program change, tmpl_gen, ndn_mode 0 or the texture-dirty bit.
4. confirmed out-of-bounds read, log only: pm_gpu.c:3894-3895 reads spr_nat_fb[20] (array 16).
5. the unit-0 TEV cache key (TevKey, pm_gpu.c:470, cache at 1430-1438) has no noise field although nd_tev_build reads k->noise.
6. R13 textured record with no handle desc and ax_ok 0 (pm_gpu.c:3440-3456): c.tex_w/h stay 0, nd_gv_params clamps to 1 (uvso for 1x1).
7. nd_tex.c:106-108: a pm_tex_load that bound an off-screen image stores key 0 and slot -1, so nd_tex_unit_hint returns 0 for it forever. (nd_tex_reset now has a caller.)
8. nd_model.c mf_tot[5] written at `sub & 7` (5-7 past the end; callers pass 1-4).
9. nd_tex.c:418-420 tile_texel reads pal[idx*2] for CI8 without a pal_n check (box pattern path into box_buf).
10. debug-only reads past the source (pm_tex_boxinfo 1919, alpha0_permille 727-732, fl1log 1508).
Row UB1: fix 1 first (store the unit-1/2 slot index and slot generation in the cache entry and refresh u[1]/u[2] from the live slot on a hit, as u[0]; or key them), then 4, 5, 8 and 6 (small, separate commits), then 2 and 3 if a gate shows them. Measurement for 1: on the layout pair (599c48970+e954 with and without the 3 pm_tex statics), count hits whose stored u[1].addr is not the live slot address. Gate: spot_mac00_det_pic byte-equal across the layout variants (55a41fa6b^ and 55a41fa6b with FB-2, the pattern build, the statics build) and nds1 head; mac_01, iwa_10, nok11_det, battle_start_f182_cold, tour10 fb unchanged or changed only by a named fix.
