# Rows BG1 and BG2: background image faults

Two agents, one per row. Both read how the background is drawn first, because the two faults can share one cause. Shared notes file: docs/handoff/agent_bg.md (each agent edits only its own section; findings that touch the other row go there AND go to the other agent by SendMessage).

## How the background is drawn (read first, both rows)
src/background_gfx.c gfx_draw_background (L336): the map background image is drawn in horizontal strips (texture rectangles, each strip a tile load of a few rows, scrolled by the camera yaw). The lists are written into the frame heap, so they run on the walker (SGEN skip class "inline words in the frame heap"). Walker side: texrect and tile load handling in 3ds/src/pm_gbi.c (grep G_TEXRECT, G_LOADBLOCK, G_LOADTILE, G_SETTILESIZE), texture slots in 3ds/src/pm_tex.c (strip keys, the TEXSTALE checks: grep pm_tex_stale_chk). Write in agent_bg.md: strip height in rows, tile size words, how a strip gets its texture slot, the texrect s/t and dsdx/dtdy values.

## BG1 FLICKER (user report, again: an earlier report is still open, see archive/diag_toadvis.md and work_queue.md line 19)
mac_00 at -57 0 76: moving left and right makes one chunk of the background flicker. Scenario bg_flicker_mac00: warp mac_00, pos -57:0:76, padscript left and right for 2 s each (stick, `left*60,right*60` repeated), shots every frame for 30 frames while moving. Name the value that changes in the flickering chunk between two shots (which strip, its texture slot, the slot content key, the s/t of its texrect). Candidates: a strip slot reused before its draw (texture cache eviction, stale key), a strip that the camera scroll splits at the image wrap (two texrects, one with a wrong s), the frame split reorder. Fix, gate: 10 shots in a row with no flicker in that chunk.

## BG2 GARBLED ROW (user report)
One row of the background does not draw right: a few garbled pixels in almost every scene. Find the row in a shot (scenes mac_01, mac_00, sbk_56: compare each row of the background with its neighbours; the bad row has pixels that do not match the image). Name the value: the last row of a strip (t at the strip end, tile size off by one row, dtdy rounding, the texrect bottom edge y in 10.2 fixed point), or the first row of the next strip, or the image wrap. Fix, gate: shots of 3 scenes with no garbled row.
