## How the background is drawn (read first, both rows)
src/background_gfx.c gfx_draw_background (L336): the map background image is drawn in horizontal strips (texture rectangles, each strip a tile load of a few rows, scrolled by the camera yaw). The lists are written into the frame heap, so they run on the walker (SGEN skip class "inline words in the frame heap"). Walker side: texrect and tile load handling in 3ds/src/pm_gbi.c (grep G_TEXRECT, G_LOADBLOCK, G_LOADTILE, G_SETTILESIZE), texture slots in 3ds/src/pm_tex.c (strip keys, the TEXSTALE checks: grep pm_tex_stale_chk). Write in agent_bg.md: strip height in rows, tile size words, how a strip gets its texture slot, the texrect s/t and dsdx/dtdy values.

## Oracle plan 2 for BG1 + BG2 (2026-11-06, Opus; worked by hand from the code, constants for mac_00: minX 12, maxX 296, zoom 6/5 about x=640 qpx, copy shift +-1184 qpx)
Pixel edges are contiguous (truncation applied to the same base on both sides of every seam), which is why skipping F07-7 changed nothing. What is wrong is the TEXTURE ORIGIN at each seam: pm_gbi.c gbi_texrect draws from pixel `xl/4` (C division, toward zero) but s0 belongs to the fractional edge xl/4; in zoom mode xl' is rarely a multiple of 4 (bg_emit *6/5: -70, -705.6 -> -705, -2131.2 -> -2131); pm_gpu_tex_rect spreads s0..s1 over the integer span ex - x0 + 1 while s1 comes from the fractional width (xh-xl)/4 + 1. Each rect's texels shift by up to 0.75 px (0.6 texel at dsdx 5/6), differently per rect and in opposite directions for negative and positive edges: at a seam a 1 px column of a duplicated or skipped texel, full sky height; the zoomed sky starts at row 0 (yl' = (80-80)*6/5 = 0), so the column touches the top edge.
Top-left and flicker: three seams fall in screen x 0..40 (game -40..0): main L/R at game -17.6 + 1.2*xOff (screen 22..40 for xOff 0..15); the fixed seam copy-R / main L at game -17.6 (screen ~22); copy-L/copy-R at game 1.2*xOff - 372.8 (screen 0..21 for xOff 278..295). The logged scroll crosses this range (xoff 14 -> 0 -> 295 at frames 123/124 and 149): the column moves, changes rounding, appears and disappears. Non-zoom mode has integer edges and does not show it.
BG2 garbled line: the same fault in y: group 2 starts at yl' = trunc((h-y0)*4.8); group 1 ends at the same base minus 4; ey and y0 take /4 and t0 is spread over the integer row count, so the boundary row repeats or skips one source row at screen row (h-y0)*1.2.
Code: src/background.c bg_emit (L91-99) `xl = (xl - 640) * 6 / 5 + 640; xh = (xh + 4 - 640) * 6 / 5 + 640 - 4; yl = (yl - 80) * 6 / 5; yh = (yh + 4 - 80) * 6 / 5 - 4;` (C division toward zero). 3ds/src/pm_gbi.c gbi_texrect (~4418): `float width = (float)(xh - xl) / 4.f;` (+1 in COPY), `pm_gpu_tex_rect(xl / 4, yl / 4, ex, ey, s0, t0, s1, t1)` with ex = xh / 4, ey = yh / 4.
Fix 1 (pm_gbi.c gbi_texrect, COPY and 1-cycle span, shared): `int px0 = (xl + 3) >> 2, px1 = xh >> 2, py0 = (yl + 3) >> 2, py1 = yh >> 2;` (arithmetic shifts: floor for negatives; px0 = first pixel whose left edge is at or after xl, the RDP rule); `s0 += dsdx_tex * (float)(px0 * 4 - xl) * 0.25f / tw; t0 += dtdy_tex * (float)(py0 * 4 - yl) * 0.25f / th;` `s1 = s0 + dsdx_tex * (px1 - px0 + 1) / tw; t1 = t0 + dtdy_tex * (py1 - py0 + 1) / th;` call pm_gpu_tex_rect(px0, py0, px1, py1, ...). Non-negative multiples of 4 (HUD, menus, non-zoom sky) give today's values (byte-equal). No division in the hot path (use a reciprocal of tw, th already computed, or the existing scale).
Fix 2 (src/background.c bg_emit, TARGET_3DS): floor division by 5 on all four edges: `static s32 fdiv5(s32 v) { return v >= 0 ? v / 5 : -((-v + 4) / 5); }` (cold, 4 calls per rect), `fdiv5((xl - 640) * 6) + 640` and the same for the others.
Proof without shots: host test 3ds/tests/bg_seam_test.c copies the arithmetic of bg_sky_rows, bg_texrect, bg_emit and gbi_texrect (old and new) and pm_gpu_tex_rect's linear s over the pixel span; for xOff 0..295, y0 0..199, zoom on and off it computes the sampled texel (floor of s at the pixel centre, same for t) for every covered pixel (game x -40..360, rows 0..239) and compares with the ideal texel (floor((xg_pre - 12 - xOff) mod 296) from the inverse zoom). Expected: old code has mismatch columns at the seams above (print xOff, screen x, rect pair); new code 0.
Gate: host test 0 mismatches; bg_flicker_mac00 shots over the xOff 0/295 crossing show no column in the top-left crop; BG2 rows at mac_00, mac_01, sbk_56; mac_01 and the pause menu byte-equal; then the orchestrator pushes, the user walks at mac_00 -57 0 76.
