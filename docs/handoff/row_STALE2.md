## Oracle plan (2026-11-06, Opus; ranked from code, nothing run)
Protected today: the native hint (nd_tex.c nd_tex_unit_hint ~104) and pm_tex_slot_find accept only a clean slot (live, not dirty, same img and tlut); the walker lookup (pm_tex.c ~1592) compares img, tlut, phash, fmt, siz, w, h, stride, dkey, then slot_valid. A slot is trusted while its source address matches and it is not dirty: everything rests on the dirty mark. slot_valid rehashes only a dirty slot (tex_inv2); the dirty mark comes from the invalidate/DMA hooks (pm_tex_invalidate).
Causes: 1 a CPU-written raster at a reused address is never marked dirty: Mario's sprite rasters are decoded by the CPU into reused buffers (src/sprite.c, the player raster cache spr_*), not through the DMA hooks; a slot keyed by an address in such a buffer passes slot_clean and slot_valid with old texels; a heap address that held a Mario frame and then holds sign texels (or the reverse after a heap reuse) binds the other image (walker and native alike). 2 the descriptor memo keyed by address (nd_tex.c nd_tex_get, diag point B): shash taken once at the first load; rewritten bytes keep the old key. 3 a compiled entity segment keeps texture state across frames (pm_gbi.c ent_draw / ent_gdl, nd_ent_segments + nd_dlc_compile hash the list words and the vertex span, not the texture bytes; a kept slot id or unit words from compile time, dlc_seg, a cached G_PM_TEXI in tb_inline). 4 unit words equal to the shadow, so no texture cache clear (nd_emit.c:74/81): console only, lower.
Measurement (one Azahar run, a scene with signposts while Mario walks 10 s: mac_00 or mac_01, padscript left and right): switches texstale plus new texsrc (cold, first 40 hits per path): on every textured bind log a path tag (walker tex_op, ent_draw segment, ent_gdl, dlc_seg, model hit, G_PM_SPR native) with img, slot, slot img/tlut, slot shash, the hash of the bytes at img NOW (src_hash over slen), and whether img lies in a sprite raster buffer (src/sprite.c TARGET_3DS logs the raster buffer ranges at allocation into a range table for pm_tex). Count per path: binds with hash now != slot shash, and binds of a sign descriptor whose slot img lies in a sprite range. One 20-shot burst of the sign during the walk. Reading: stale binds with img in a sprite range: 1. memo key differs from the slot hash: 2. only ent paths bad with the slot sgen changed since compile: 3. hashes clean but picture wrong (console only): 4.
Fix: 1 src/sprite.c under TARGET_3DS after each CPU raster decode/copy into a reused buffer: pm_tex_invalidate(ptr, len) (slot dirty, slot_valid rehashes); slots whose img is in a registered sprite raster range keyed by (img, shash); cost one call per raster upload. 2 nd_tex_get on a memo hit: if the hinted slot is not clean or its sgen changed, reload via pm_tex_load and refresh e->key and e->w; no memo for descriptors in a sprite raster range. 3 entity segments store the descriptor (img, pal, fmt, size), never a slot or unit words; each draw resolves via nd_tex_unit_hint; a sgen change recompiles or falls back for that segment. 4 pm_tex_slot_unit / native submit sets u->force = 1 when the slot sgen differs from the last native unit 0 write.
Gate: a 30 s walk at mac_00, mac_01 and dro_01: texstale and texsrc stale counts 0 on every path; 20 consecutive shots of the signpost while Mario walks: the sign crop stays the same; ent and native hit rates within 2 percent; mac_01 byte-equal at standstill; then the orchestrator pushes, the user checks a sign.
