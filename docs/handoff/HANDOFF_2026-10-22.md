## 1. PROJECT STATE

### 1.1 What the port is
A port of Paper Mario (N64, US ROM, decompilation in this repo) to the Nintendo 3DS (homebrew `.3dsx`, devkitARM, citro3d, ndsp). The port layer is in `3ds/src` (pm_gbi.c = N64 display list interpreter, pm_gpu.c = PICA200 submit, pm_tex.c = texture cache, pm_comb.c = RDP combiner to PICA, pm_phase.c = phase timers, pm_warp.c = debug switches, pm_options*.c, pm_route.c, ...). The game logic is the decomp code in `src/`. The ROM is read at run time from the SD card (`sdmc:/3ds/PaperMario/papermario.z64`), the 3dsx holds code and code-side data only. All 421 maps are linked. US only. S28 (first hardware boot) is done. Now: hardware tests by the user, then performance.
Build: `sh 3ds/build.sh` (Docker/devkitARM; lane builds with `PM_LANE=laneB`/`laneC`, output `build3ds/lane-<lane>/`). Build number = 797 + (commit count - 3172), constants in `3ds/build_base.txt`, header `3ds/include/pm_build.h`. Main tip 35676d3b3 builds as 1015. Suffix `-laneB` only for lane B.
Azahar (emulator, Linux flatpak `org.azahar_emu.Azahar`): `3ds/run_azahar.sh` (fast mode `-F`), `3ds/tools/golden.py`, test budget in `3ds/logs/test_budget.csv` (8 starts per row, `PM_ROW=<row>`). Azahar numbers are a reference for direction and counters. The console decides.

### 2.4 Push (the orchestrator pushes, not an agent; the user must see it)

### 2.6 Push PLAY and Push SAVE (docs/plans/hw_batch.md section 8.0)
Push PLAY (speed and DLC A/B; the user plays by hand):
```
sh 3ds/push_3ds.sh --no-build --ip $O -t 20 dspaudio audiostat texstat pacestat logstat phase phsum abtog=base,dlc:60 loglevel=debug
```
`abtog` turns the display-list cache `dlc` on and off every 60 drawn steps. After the play: HOME or Select menu "Exit to Homebrew Menu", start the FTP app, pull. Read-out of the pull file P: `grep "abtog " P`; `grep -E "^#[0-9]+ (phs|phh|phc) " P` (gb/gd/gp per state); `grep " dlc" P`; `grep "pace:" P`; `grep " spike " P`; `grep texstat P`; `grep -E "dspaudio: (first aux callback ran|aux mask)|audio dsp:|audio2:|audio cost" P`; `grep -E "FAIL|CRASH|lines dropped" P` must be empty or 0; `grep "exit:" P` shows a clean shutdown. Audio fallbacks: add `dspfx=off`, then `dspgain=50 dspflush`, or drop `dspaudio`.
Push SAVE (save block, pipe, Merlon door faults PT42 PT45 PT46 PT47 PT26):
```
sh 3ds/push_3ds.sh --no-build --ip $O -t 20 dspaudio audiostat pacestat logstat phase phsum camlog entlog mtxlog nogv1 noraw1 nofl1 fs1off loglevel=debug
```
If the faults vanish, push again with one switch dropped at a time (`nogv1`, `noraw1`, `nofl1`, `fs1off`). `camlog` writes up to 60 lines per second, `mtxlog` 50 per 30 frames: keep the session short and note the minute of each fault. Copy the pull to `3ds/logs/perf/hw_${B}_SAVE_pull.txt`.
