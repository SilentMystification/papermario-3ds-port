# Row LOG: logging with negligible game cost, one source for three sinks, new Logging menu

## Goal (user, 2026-11-06)
Logging on must have negligible impact on gameplay performance, also in a logging storm. Logging menu: a submenu with a global Logging On/Off; Off greys every row below; On: Live Log, Log to Disk, Console Log, each with a level or Off; all three read from one source, so more sinks cost as little as possible.

## Oracle plan (2026-11-06, Opus; cycle figures are estimates, LOG1 measures them)
Today per kept line on the game thread: level test, CAS, vsnprintf into the 256 B slot (about 5 to 20 us), lognull strstr, release store, and a LightEvent_Signal syscall when the queue was empty (about one per line at low rate; pm_log_prof_line wakes on every line). Writer and sink on core 1 make many small send() and SD calls; on the O3DS the SOC and FS modules also run on core 1. About 800 pm_log* call sites.
(1) Deferred formatting. Slot 128 B, 32 B aligned, SLOTS 1024 (128 KB): header 16 B (const char* fmt, u32 seq, u32 frame, u8 lv, flags, nw, sbytes), up to 16 argument words, then a string area. Per-call-site descriptor cache `static LogDesc ldesc[512]` direct-mapped on (fmt >> 2) & 511, 8 B each (fmt, nw, kind mask 2 bits per argument: word, 64-bit, double, string); a miss scans the format once (flags, `*` width/precision as int, l/ll/h, d i u x X c p s f g e; refuse %n and over 16 words); a hit is one load and compare. Copy with va_arg per kind (u32; u64 and double as 2 words at an even index); %s copied now into the string area (truncated), offset stored; %.*s copies at most that length. Fallback: fmt not in the read-only image (address test against the 3dsx link script symbols) or a refused descriptor: format now as today into the string area, flag bit. Timestamp: seq plus the frame number (no svcGetSystemTick). Writer: log_fmt(slot, out) walks the format and calls snprintf per conversion with the typed argument (16 B spec buffer): output byte for byte as vsnprintf. Estimate about 80 to 120 cycles per kept line; target under 1 us (268 cycles) with up to 2 %s of 16 chars, a dropped line under 50 cycles.
(2) One queue, three sinks: lv_live, lv_disk, lv_con each -1 (off) or 0..3; log_on global. pass_lv = log_on ? max(enabled) : -1, set in pass_recalc. vlog first line `if (lv > pass_lv && !prof_force) return;` (global Off = one load and return; the log_file_on test merges into it). Writer per batch formats each slot once (only if some sink wants it) and fans out: disk (fb_put) if lv <= lv_disk; socket if a client and lv <= lv_live (plus ring_add); console (cb_put, body without #seq) if lv <= lv_con. Prof lines (flags bit) disk only. lognull moves to the writer.
(3) Storm: queue full = one atomic add and return before the descriptor lookup; the writer prints `log: dropped N` once per batch. No wake per line: remove LightEvent_Signal from vlog and pm_log_prof_line; pm_log_frame_tick() called once per drawn frame after FrameEnd in pm_main.c; one edge-detected signal at half full. Writer and sink on core 1 prio 0x3F: at most 128 slots per drain then accept_client and read_cmd; socket one send per 64 ms or 16 KB; disk one SD write per 250 ms or 32 KB; console 10 per s. The game thread never takes a lock, calls a service or waits; a full fb drops the disk copy (counted), no wait on fsink_lock; a full socket drops the live copy only.
(4) Menu: Debug tab folder "Logging and Profiling >" (pm_options.c fl_name, RW_LOGF) keeps Profiling and opens a new page "Logging" (sub_kind, new RW_LOG* ids): "Logging: On/Off" (A toggles), "Live log", "Log to disk", "Console log": Off/Error/Warn/Info/Debug (< > and A cycle). Off greys and skips the 3 rows: add pm_optui_grey(tab,row) next to pm_optui_readonly (pm_options.c ~340), used by the cursor skip (pm_options_ui.c ~111) and the row colour. Remove the old dbg_lbl rows "Logging", "Log level", "Console level" in the same row (CLAUDE.md rule 7). options.ini version=2 keys log_on, live_level, disk_level, con_level (-1 off, 0..3); read migration from v1 (log -> log_on; loglevel -> disk_level and live_level; conlevel 4 -> con_level -1, 0..3 kept); write only new keys. Switches: log=off, loglevel= (disk and live), conlevel= (console), new livelevel=, disklevel=; precedence launch argument, then options.ini, then default. pm_log_prof_row saves and restores the three levels.

## Oracle plan E: writer stops after 11 lines (console, after c5101ddb0; must be in LOG2 or LOG4)
Facts: 11 lines then silence; a reconnect is accepted and ring_replay sends the same 11 lines: the writer loop lives, but drain_locked delivers nothing new, not even writer_beat; last beat queue 1 of 1024.
Cause 1 (high): a slot reserved and never committed at q_tail: vlog reserves with the q_head CAS, formats, then sets state 1; drain_locked stops at the first slot whose state is not 1, so one producer that stalls between the CAS and the commit blocks all later lines forever. Likely a lower-priority thread on core 0 (pm_step worker 0x30, audio) preempted by the game thread after its CAS. With prof=4 those debug lines failed the level test and never reserved. Cause 2: the gate closed after boot (log_file_on 0 or pass_lv low). Cause 3 (fsink_lock) rejected: the reconnect was accepted.
Measurement: writer_beat sends a direct status line straight to the socket and fb_put (not via vlog): `beat hb %u head %u tail %u tstate %u tage_ms %u tthread %08x file_on %d pass_lv %d` (add u32 th to Slot, written right after the CAS; tage_ms = time tail stayed uncommitted). Console push with the same switches, then pull log.txt after exit.
Fix (cause 1): a stalled producer never blocks the queue: lap-tagged slot state (state = (lap << 2) | 1 at commit, lap = h / SLOTS via shift); the producer commits with a CAS from "reserved this lap" and drops (counted) if it fails; drain_locked marks a tail slot uncommitted for over 50 ms while later slots are committed as abandoned (CAS to (lap << 2) | 2), counts it, moves on. Keep the reserve-to-commit window short (with deferred formatting it is a few stores). Gate: console push loglevel=debug texstale waterlog: lines through 240 s, a beat every 5 s, abandoned count shown, log.txt complete, a reconnect continues with new lines.
