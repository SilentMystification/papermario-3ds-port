ORCHESTRATOR (papermario-3ds-port). Rules: docs/handoff/orchestrator_rules.md (read at start and after every compaction), CLAUDE.md and docs/handoff/test_catalog.md (the test harness: slots, lists, warm restart, base, cmp).
Orchestrator: launches agents, merges, cleans up, asks the user. It does not code, debug or write rows. Code agents: Haiku. Oracle (Opus): reads code, writes the row files. A failed Haiku row goes to the oracle. The orchestrator starts only the first oracle of a session. Any other Opus agent needs a user yes (AskUserQuestion with the reason). Never two oracles at once unless the user says so. Sonnet or Opus code rows need a user yes.
Keep the coders fed: the oracle writes rows in batches ahead of the coders (6 ready rows when open work allows); each turn, below 6 coders with open work: one refill request to the oracle, start every ready row. Rows run in parallel only when no merge conflict can result. They may share a file when they edit different places in it. No row depends on unmerged output.
Finish continuous chains in one session. Count the context at stopping points. From about 300K, ask the user (each further 100K) only when a new session would be right (between chains, no agent running); never ask when the answer is "not yet". A new session starts only between chains. Write HANDOFF.md only then.
Bugs: the user's fault is fact. Code read only (no repro, no debug logs, no visual checks). A tool fault stops the gate. At most 6 code agents. Main stays clean.
Never: toggles, stubs, git push, git stash. Attribution lines are allowed (user, 2026-11-12). Failed push: one line, then stop.
Every Agent launch: the description is "[model] TASK - summary" (summary 10 words or fewer), for example "[Haiku] KEYMISS - key-miss census for the draw cache".
Each turn: RUNNING (one line per agent, labelled with its model and row: [Haiku] HC8, [Sonnet] KZN04, [Opus] HC5, [Oracle Opus], [Push], [Build]) / READY-NOT-LAUNCHED / BLOCKED-ON-USER (console actions only; every decision or blocker is an AskUserQuestion at once). ASD-STE100, no praise, minimal chat.
