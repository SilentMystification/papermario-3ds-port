### 1.2 Main loop and game step

- pm_frame_loop: one pass per iteration. pm_pad_scan runs at :374 before any game work. CONFIRMED 3ds/src/pm_main.c:362-374.
- The idle pass (`!draw`) runs pm_gfx_retrace for the other retrace, the interpolation key frame and the schedule wait. CONFIRMED pm_main.c:376-407.
- The game step is pm_gfx_retrace (pm_main.c:463) or pm_gfx_retrace_skip (:440). Both call gfx_func, which is gfxRetrace_Callback, which runs step_game_loop. CONFIRMED 3ds/src/pm_nusys.c:141-153.
- After a stall the schedule keeps at most 3 steps owed. CONFIRMED pm_main.c:479-483.
- pm_warp_tick (boss, bypass, battle hooks) runs once per step. CONFIRMED pm_main.c:488, pm_warp.c:698-712.
- The bottom screen shot (`shotbottom=<frame>:<count>`) is keyed to the step counter `frame`. CONFIRMED pm_main.c:537-560.

## 2. Design

### 2.1 Select menu pauses the game (spec: "pause the game immediately (not the pause screen)")

Freeze point: in pm_frame_loop, after pm_pad_scan (pm_main.c:374) and before the `if (!draw)` branch (:376).

```c
if (pm_menu_open) { menu_frozen_pass(); continue; }   /* no game step, no draw, no audio tick */
```

menu_frozen_pass (pm_main.c, about 15 lines):
1. First pass after the open: log `menu: game paused at frame %u`, call pm_gpu_menu_grey() (2.2).
2. Every pass: gspWaitForVBlank() (60 scans per second, the pad script and the menu repeat keep their rates), pm_log_poll is already done at :373, run the menu shot tool (2.10).
3. The step counter `frame`, pm_frame_n, nuGfxCfb_ptr, the interpolation state and pm_warp_tick do not change. So the game resumes in the exact state, and the frame buffer parity of the pause code (PT78, pm_main.c:254-260) stays valid. INFERRED.

Resume (first pass with pm_menu_open 0): set `sched_next = 0` and `step_vb_ok = 0`, log `menu: game resumed at frame %u`. Without this the schedule owes up to 3 steps and FS1 skips the first draws (pm_main.c:424, :479-483). INFERRED.

Menu actions that need game steps (warp, boss, battle, title) close the menu first (pm_options_ui.c:99-110), so they run on resume. CONFIRMED (act result 5 and 4 close the menu).

Audio: pm_audio_step is not called, so no new mixer ticks. The DSP plays the queued buffers and then stops. INFERRED (no underrun fill code found in pm_audio.c; au_underrun is a counter, pm_audio.c:17). The row checks the log for an underrun warning flood on resume.

Watchdog: pm_wd_prog++ runs at the loop top (pm_main.c:364), so the watchdog sees progress. CONFIRMED.

The pause screen (GAME_MODE_PAUSE) and battles freeze the same way. No game mode is special.

### 2.2 Grey top screen while paused

Facts:
- The top screen gets the render target through a display transfer to RGB8 at C3D_FrameEnd. CONFIRMED pm_gpu.c:1244-1248 (left), :1254-1258 (right eye).
- gfxInitDefault puts the screen frame buffers in linear FCRAM (not VRAM), double buffered. INFERRED (libctru gfxInitDefault = gfxInit(BGR8, BGR8, false)). pm_gpu.c:1224 calls gfxInitDefault. CONFIRMED.
- The end-of-frame clear is queued only for a frame that drew, before that frame's command list, so after a frame ends the render target holds the finished picture. CONFIRMED pm_gpu.c:1879-1882.

Options, cost on the O3DS:

| Option | Work | Per paused frame | Shared draw path | Mark |
|---|---|---|---|---|
| G1 CPU, once (recommended) | 2 empty citro3d frames (FrameBegin, FrameDrawOn target and targetR when stereo, FrameEnd) so both screen buffers hold the last picture, then one CPU pass over the back buffer of GFX_TOP left (and right when gfxIs3D) with y = (77 r + 150 g + 29 b) >> 8, flush that span once, gfxScreenSwapBuffers | 0 | no (new function, not called by a draw) | INFERRED: 240 x 400 x 3 = 288 KB per eye, 9000 cache lines, about 1.3 M cycles, about 5 ms once on the O3DS |
| G2 GPU texenv | GX_TextureCopy of the target into grab_tex (exists, pm_gpu.c:1677-1695), one quad, stage 0 GPU_DOT3_RGB with constant (0.5 + w/4), stage 1 add 0.5 | about 0.2 ms if redrawn, 0 if once | yes: shader, attribute and texenv shadow state of pm_gpu.c | INFERRED |
| G3 colour matrix on the composite | the PICA has no colour matrix on the display transfer | - | - | INFERRED (GX_TRANSFER flags have format and scale only) |

Recommendation: G1. hw_guidelines.md rule 3 (sequential walk) and rule 8 (write, then one flush) hold. The CPU must not read VRAM (hw_guidelines.md:9): G1 reads only the linear screen buffer. Wide, native, fullscreen and stereo need no own code: the pass covers the whole 400 x 240 buffer of each eye that is on.

Function: `void pm_gpu_menu_grey(void)` in pm_gpu.c beside pm_gpu_menu_draw (about 35 lines). Rule 5: pm_gpu.c is shared draw code, but the function runs only from the frozen pass, so no byte-equal check on other scenes is needed.

Option: a Video row "Grey on pause" is not in the spec. Not planned.

### 2.4 Submenus (spec: "i want submenus")

Model: a page is a row list. Pages 0 to T-1 are the tabs. Pages from PG_SUB up are folders. A folder row has id `RW_DIR + page`. A is "enter", B is "back".

- Row ids become `kind << 12 | index` (kind: 0 plain, 1 input map, 2 debug toggle, 3 stat, 4 boss, 5 battle, 6 badge, 7 key item, 8 partner, 9 spawn item, 10 warp map, 11 folder, 12 cheat toggle). The old fixed ranges (100, 200, 300, 310, 400) cannot hold 80 badges or 400 maps. INFERRED.
- Large pages (badges about 80, items about 250, maps per area up to about 40, battles per area up to about 30) are not built into an ids[48] array (pm_options.c:268, :274). Two functions instead: `page_count(pg, mode)` and `page_id(pg, i, mode)`, one switch each. No table of function pointers.
- The pm_optui_* functions take a page in place of a tab. act returns 6 = enter page (page in `pm_optui_enter`). The Back row of a folder and the B key pop.
- Stack: `struct { int pg, sel, top; } stk[4]; int depth;` in pm_options_ui.c (mode 1) and the same in filemenu_options.c (mode 0). Depth 4 covers Debug > Boss > Battles > area. L and R in a folder: pop to depth 0 and change the tab. INFERRED design.
- Breadcrumb: at depth > 0 the tab line shows the path, for example `Debug > Boss > Battles > KMR_1`, cut from the left to 38 columns. The blank line (2.3) stays. See question Q3.
- Mirror rule: the file select panel shows the same pages. Rows that need a loaded save (Cheats tab, Boss, Battles, Warp maps live) are hidden in mode 0 (gPlayerData is replaced when a file loads). See question Q4.

Target tree (mode 1):
