# Row SBK: sbk_56 level siding lighting blown out (Azahar and console)

## Oracle plan (2026-11-06, Opus; causes ranked from code only)
sbk_56 map models have lighting baked into vertex colours (sbk_56/main.c SetSpriteShading NONE; only MODEL_o49 water has a panner), so a lit-model (pm5, nd_lights) fault is unlikely. Native paths that changed this colour maths: SGEN-2 two-texture combines (nd_raw_native combine 8, plan.uses_tex1, unit 1 pm_tex_native_unit1, uvx, 47c53a895); the boost path, cycle 2 (SHADE-ENV)*COMBINED+COMBINED: pm_gbi.c sets rgb_scale 2, the walker CPU path halves the vertex colour (pm_gbi.c ~2797), nd_model.c:43 halves cm/ca; nd_tmpl.c nd_tev_build applies rgb_scale == 2 only in the `tex` branch (classes 2/3), the combine 8 branch uses only the plan stage scales.
Causes: 1 two-texture weight wrong on the SGEN-2 native path (the lerp factor PRIM_LOD_FRAC, LOD_FRAC, ENV or PRIM alpha missing from the native TEV constant, so TEXEL1 gets full weight; or unit 1 samples the wrong image: uvx, panner tile 1, i8_1 = 0). 2 boost applied twice or half on the native path (plan x2 and the vertex colour not halved, d.cmul/d.cadd from g_cmul/g_cadd, or the reverse). 3 a TEV stage scale word wrong (nd_tmpl.c ev_scale). 4 lit pm5 double light (only if the siding is lit). 5 WIDE1 (ortho only, lowest).

Run 2: switch sbklog, one line per nd_raw_native and model draw in frames 200-201: tmpl id, combine, plan_k[0..3], plan.n, tex/tex1, i8_0/i8_1, rgb_scale, boost flag, 6 TEV stage words (ndn_to.st[i][0..4]: src, op, func, const, scale), d.cmul, d.cadd, prim, prim_lod, env, u0/u1 address and type; with notex1nat log the same batch on the walker close (flush_draw_cpu: TEV words, vertex colours).
