## Oracle plan 3 (2026-11-06, Opus; after 3a: blocker combine right, surface zm 1 0, alpha 153, still no water over the bed)
N64: the real water record has IGNORE_MATRIX (0x2811): blocker and surface use the matrix already on the stack. The copy (VALID|HAS_LOCAL_VERTEX_COPY, no IGNORE_MATRIX) does MODEL_MTX_OP(finalMtx, LOAD|PUSH), draws nothing, gSPPopMatrix: the stack after the copy equals the stack before, so blocker and surface use the same matrix.
Causes: 1 matrix stack wrong after the copy record (pm_gbi.c rec_run/rec_apply: load_mtx without a real push, or a push and pop that do not pair, q[12].words.w1 / gbi_popmtx(64u)): the surface draws with the copy's finalMtx (transform twice: shifted and deeper) or the entry below the top. 2 the record geometry draws with R1/R2 although IGNORE_MATRIX is set (pm_gpu_model_native / nd_model_draw, or the fallback rec_dl after rec_apply loaded a matrix). 3 depth map (decal bias sign sh_depth_map / R_DM_OFFSET; zm already 1 0, decal 0): low. 4 ZMODE: low.
Measurement (one run pond_mac00_wlog, waterlog, edits from scratchpad/pond2): wdraw adds `gm %u` (pal_g[0]) and a hash of pal[0] (16 floats); for vertex 0 of the batch clip z/w and screen x,y computed on the CPU from palk[0] and the ring vertex; wrec adds the matrix stack depth before and after each rec_run of model 0xD6 and its copy. Expected: blocker and surface same gm and hash, surface vertex 0 inside the pond outline and nearer than the bed, stack depth equal across the copy. Hash differs or depth changes: cause 1 or 2. Same matrix and surface z behind the bed: the vertex data (copy local vertex list vs the real model list; recGeom in model.c). Check shot with switch wsurfalways (om 0c1849d8 frames 200-201: depth test ALWAYS): water at the right place over the bed = depth (1 or 3); water elsewhere = matrix (1 or 2).
Fix (pm_gbi.c): 1 load_mtx with G_MTX_PUSH pushes; the copy's pop pops exactly that entry; rec_matrix on the cached path uses the same push rule as rec_apply. 2 IGNORE_MATRIX (R3 bit 256): neither the native model path nor the fallback loads or applies R1/R2.
