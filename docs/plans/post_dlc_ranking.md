## Verification in code (lane B, 2026-10-22)
(a) On the GPU with GV1, RAW1, FL1 on (defaults, 3ds/include/pm_gpu.h:121-122): vertex transform by the matrix palette, viewport and tilt (3ds/shaders/pm4.v.pica: `dp4 r5.x, pal[a0.x], r1`), UV scale (`uvso`), colour scale and offset (`cmul`, `cadd`), z mix (`zmix`), PICA clip, PICA cull (`g_cullm`, pm_gpu.c, set from the geometry mode in pm_gpu_gtrip and pm_gpu_grange), colour combine through the TEV stages (pm_gpu.c flush_draw, TevKey). Fog mix, lighting and texgen are NOT on the GPU: pm_gbi.c:1275-1276 `if (geom & (G_LIGHTING | G_TEXTURE_GEN)) return GVR_LIT; if (fogmix_on && (geom & G_FOG)) return GVR_FOG;` and the lit vertex load at pm_gbi.c:2307 (GVR_LITLOAD). On the CPU per vertex (default, non DLC load): the matrix product and the clip bits (pm_gbi.c:2338-2347: `p[0] = m[0][0] * x + ...; vert_cb = clip_bits4(p) | near`), 8 slot array stores (vert_ring, vert_gmi, vert_tss, vert_mid, vert_live, vert_scr, vert_gvf, vert_cb). On the CPU per triangle: slot checks, box-bit AND reject, near/scr/tss refusals, epoch test (gv_tri, pm_gbi.c:1285-1305) and one index append (pm_gpu_gappend). With DLC the replayed groups skip all of it (pm_dlc.inc.c dlc_static_group: one pm_gpu_grange per segment).
(b) PO3 slices in the tree: PO3a counters (po3a_on, pm_gbi.c:2279), PO3b raw Vtx ring and u16 index ring (pm_gpu.c gring, gidx, pm_gpu_gtri), PO3c colour, uv and z mix uniforms (cmul, cadd, uvso, zmix in pm4.v.pica), PO3e GPU cull and clip (g_cullm, PICA clipper), PO3g default on in the form of GV1 (PM_GV1_DEFAULT 1, `gpuvtx` kept as switch). Not in the tree: PO3d lighting in the shader (lit loads fall back, GVR_LIT, GVR_LITLOAD) and the per-vertex fog factor (GVR_FOG). PO3f (console picture check) was done through the user hand tests.
(c) The statement "the PO3 gate is closed" holds for the gate (PO3b/c/e are done and default on through GV1). It does not mean "no CPU work per vertex is left": the CPU transform and clip bits of a non-DLC G_VTX remain. Azahar test of removing them (switches gv1raw: no reject bits; gv1box: one box test per load), toad without DLC, gb: default 10.64 ms, gv1raw 12.46 ms (draws 70 to 131), gv1box 10.77 ms. Letting the GPU reject everything is slower, so PO3 stays closed: no gain.

## OPT-TS: texture state skip (row OPTTS)
Cause: the PG1 skips in G_SETTILE (same tile 0 definition) and G_SETTILESIZE (same texture) compared pm_tex_epoch(), which every texture load and pm_tex_origin bumps, so they never hit (gbiprof: tile0 same 0 of 161, tilesize loads skipped 0 of 162). The wrap state only changes in pm_tex_set_wrap. New counter pm_tex_wrap_gen (set_wrap and frame start) for the G_SETTILE test. Result: tile0 same 88 of 161, loads skipped 31 of 162, empty flush calls 923 to 804 per step, gb 8.11 to 8.01 ms (-0.10 ms, console about -0.4). Draws unchanged (73). statehash equal with and without (`nowg`) on yard and battle, dlccheck zeros, golden toad and yard 0.00 with `--extra dlc`. Switch `nowg` and abtog state `nowg` give the old behaviour.

## GV5 lighting and texgen on the GPU (row LIT, lane B)
Change: lit vertex loads go to the ring like unlit ones (the load refusal GVR_LITLOAD is gone for the normal case). The normal matrix (rows 0 to 2 of the model view matrix at the load) is part of the gm_tab entry (gv_matrix_id(need_nm)). A lit batch uses pm5: lflag.x lighting, lflag.y texgen (lighting on and G_TEXTURE_GEN), the light table (ambient, 7 lights as colour and direction / 127) and the look-at vectors as uniforms, uploaded once per change of the block (PmFx). The RSP lights at the vertex load, so a vertex keeps its lit state (vert_litf): a triangle whose vertices were loaded with another lighting state, or after a light change (lit_freeze makes the colour with the old lights and keeps the vertex on the CPU path), takes the CPU path. Static DLC groups are lit-capable when the lighting state does not change inside the group; else the interpreter runs them.
Bug found in the test: the PICA uniform registers are one file for all programs, so a pm5 draw wrote over the pm4 palette that the lean shadows believed to be there (the ceiling of isk_01 lost its texture). The shadows of pm4 and pm5 are cleared when the other program writes.
Checks: no scene has lit triangles with non-zero lights except a few in the battle stage (isk_01 has a lit object with zero lights), and none uses texgen. Test with test lights and with lighting plus texgen forced on every draw (temporary switches, removed): the whole picture of toad (frame 251) and yard (249) lit and environment mapped: GPU against CPU 0.000 percent of pixels over 8, max 1. isk_01 with test lights: max 1. Counters (regression guard): battle draws 119 to 119, vertex slots 2668 to 2668, gb 4.79 to 4.75 ms; isk_01 draws 70 to 70, gb 3.31 to 3.28 ms; litload refusals 666 to 0 per 300 frames. statehash equal (battle 7e1f3949 as before), dlccheck zeros, golden toad 0.01, yard 0.00, battle 2.47 (unchanged).
Regression found and fixed in the same row: lit_freeze scanned the 64 vertex slots at every light op (190 G_MOVEMEM per step in town): gb 7.78 to 8.50 ms. It now returns at once unless a lit vertex was loaded since the last freeze (lit_pending): gb 7.78 ms (before the GV5 rows 7.69, the rest is the new state checks).

## TEXEL1 on the GPU path (row TEX1)
The GVR_TEX1 refusal sent every triangle of a two texture combiner to the CPU path: tik_01 30416, iwa_00 19620, kmr_03 4800 per 300 frames. The epoch prep (ensure_tile, dual_bind) already loads tile 1 into the second texture unit and sets the uv map uvx, and the raw draw binds the aux texture and writes uvx, so the GPU path only has to accept it. Refusal stays for a TEXEL1 that is an off-screen slot (t1_fold per draw), a missing tile and for lit or fogged batches (pm5 has no second coordinate). ## Raw triangle stream and removal of the CPU transform: measured, not done (rows GBI1, FOG, lane B)
Azahar, toad without DLC, one run each: default gb 10.64 ms, 70 draws; gv1raw (no CPU transform and no per triangle reject, only a near test per load) gb 12.46 ms, 131 draws, 910 triangles to the GPU against 252; gv1box (one box test per load) gb 10.77 ms, 75 draws. Cause: a triangle that the CPU rejects never touches the state, so it opens no batch; without the reject every off screen model reaches its texture list and splits a batch (each draw about 79 us on the console). The GPU clip does not help, the cost is the CPU draw call per split batch. The per vertex transform is the cheapest test that tells a model is off screen, so it stays. The static DLC groups already test one box per group and skip state, vertices and triangles together. The PICA does clip, cull, light, fog, texgen and TEXEL1 for all triangles that do reach it.
