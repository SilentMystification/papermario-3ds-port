# F07 plan (planning only, 2026-10-18)

Research: docs/HISTORY.md section "Widescreen and 60 fps research" (paperboat and sm64-3ds file references). Rules: 3ds/AGENT_RULES.md. Each slice adds at most 10 KB of code. Model: sonnet per slice.

## Scope
The top screen is 400x240. Today the game draws 320x240 with two 40 px bars. Widescreen = use all 400 px (aspect 5:3, X scale 1.25). The logic stays 320x240. Opt-in with switch `wide` first. 3D stays off.

## Facts (from the code)
- 3ds/src/pm_gpu.c: `px()` = 40 + x (line 914), scissor top/bottom = 40 + sci_x (lines 312-313), scissor clamp to 320 (lines 694, 868), frame copy 320x240 for game code (`D03`, lines 550-569).
- 3ds/src/pm_gbi.c: G_MOVEMEM viewport. `clip_bits` works in clip space, so a wider viewport needs no change there.
- src/cam_main.c:65 `guPerspectiveF(... viewportW / viewportH ...)`. src/model.c:2804 cull `xComp >= -1.0f && xComp <= 1.0f`.
- UI: SCREEN_WIDTH in 268 lines of 56 files. Most: background_gfx.c 33, hud_element.c 12, msg_draw.c 10, screen_overlays.c 10, screen_render_util.c 10, draw_box.c 5, curtains.c 5.

## What can start before the graphics rows
Nothing in code. Every slice touches pm_gpu.c, pm_gbi.c, model.c or draw_box.c. Only the user question (F07-6) can go now.

## Conflicts with the graphics rows
- pm_gpu.c `px()`, scissor, offscreen slots: B1, B2, B3 (slot roles, grabs), V10 (`box_pattern_rect` draw path). F07-1 waits for them.
- pm_gbi.c viewport movemem: B1-B6, F08 edit pm_gbi.c.
- Frame grabs and the z-buffer (B2 role T2, B5 underwater, F03 depth readback): with `wide` the grab must map 400 PICA columns to the 320 N64 image. A wrong mapping gives a shifted grab. Check each one again in F07-5.
- src/model.c: V13 may change the tex pan or the model draw. F07-2 waits for V13.
- draw_box.c: V10. F07-3 waits for V10.
- PO3 (docs/plans/PO3_row.md): PO3 moves the transform to the vertex shader. The 1.25 scale must then live in the viewport uniform, not in `px()` on the CPU. Do F07 before PO3, or include the scale in the PO3 viewport.

## Risks
- Objects pop in at the edges (culled by the game at 4:3). F07-2 widens the main cull. Other cull sites (npc.c, effects) can need the same change. Grep for `xComp` and SCREEN_WIDTH tests.
- UI drawn in N64 pixels stretches or shifts. Many per-element patches (paperboat lists about 15 files).
- Frame grab size (320x240 in N64 memory) stays. Grabs show only the center. Pause blur edges can show a seam.
- Scripted camera shots in cutscenes show off-stage objects at the sides.

## O3DS cost (estimate from Azahar, not hardware)
- Fill: 400x240 instead of 320x240, +25 percent pixels. The PICA fill is not the limit today (PT01: the cost is the CPU GBI walk and the flush).
- Geometry: the wider cull draws more models. Estimate +10 to +25 percent GBI interpret time, about +1 to +4 ms per frame (11.1 to 15.3 ms today).
- The O3DS is estimated at 32 to 42 ms cpu per frame in heavy maps today. +4 ms can push more frames over 33 ms (20 fps). Keep `wide` off by default on the O3DS. Measure in S28 with `pacestat phase wide`.
