# F07 plan (planning only, rewritten 2026-10-18)

Rules: 3ds/AGENT_RULES.md. Model: sonnet per slice. 60 fps is row F06 (docs/plans/F06.md).

## User decisions 2026-10-18 (they replace the old plan)
1. Widescreen is a toggle on the N3DS AND the O3DS. The O3DS can run slower. That is not a reason to remove it there.
2. Build F07 BEFORE the S28 hardware test, as a code switch `wide` that defaults to off. The UI toggle comes later with row F11 (options menu).
3. The default stays 4:3 at 30 fps. With `wide` off, the picture does not change (golden 0 diff).

## Source
- PaperBoat, the Harbour Masters PC port of Paper Mario 64 (https://github.com/HarbourMasters/PaperBoat), local checkout reference/paperboat, commit 282c269b3741. Research notes: docs/HISTORY.md, section "Widescreen and 60 fps research".
- PaperBoat method: the game stays 320x240 logically. The projection aspect changes for CAM_DEFAULT and CAM_BATTLE (src/cam_main.c:61-68, src/port/patches/CameraPatches.cpp:128-134). The vertical FOV stays. The viewport and the scissor get wider (cam_fit_viewport, get_cam_scissor_x). Right-edge UI uses edge helpers (Engine.cpp:1415-1481). The model cull uses wsCullX = aspect * 3/4 (model.c:2845). UI is patched per element. Backgrounds tile (BackgroundPatches.cpp). Curtains use k = aspect / (4/3).

## Scope
The top screen is 400x240. Today the game draws 320x240 with two 40 px bars. `wide` uses all 400 px (aspect 5:3, X scale 1.25). The logic stays 320x240. 3D stays off.

## Facts (from the code, 2026-10-18)
- 3ds/src/pm_gpu.c: `px()` = 40 + x (line 1040), viewport uniform `view.r[0].w = 40 + vp_tx` (line 91), scissor top and bottom = 40 + sci_x (lines 338-339), scissor clamp to 320 (line 695), frame copy 320x240 for game code (`D03`, lines 591-610), grab strips at 40 + x (lines 723-732).
- 3ds/src/pm_gbi.c: G_MOVEMEM viewport. `clip_bits` works in clip space, so a wider viewport needs no change there.
- src/cam_main.c:65 `guPerspectiveF(... viewportW / viewportH ...)`. src/model.c:2804 cull `xComp >= -1.0f && xComp <= 1.0f`.
- Letterbox viewports `set_cam_viewport(CAM_DEFAULT, 12, 28, 296, 184)`: state_file_select.c:71 and 110, state_logos.c:99, state_title_screen.c:206.
- UI: SCREEN_WIDTH in 268 lines of 56 files. Most: background_gfx.c 33, hud_element.c 12, msg_draw.c 10, screen_overlays.c 10, screen_render_util.c 10, draw_box.c 5, curtains.c 5.

## Debug switches
- `wide`: 400 px widescreen. Off by default. F11 later sets the same flag from the options menu.
- Used with it: `shots`, `shotwin`, `autoa`, `tour=`, `pacestat`, `phase`.

## Memory (no cap, user decision 2026-10-18; report the size)
- Each slice reports the 3dsx size change in its commit and in PROGRESS.log.
- Estimate: code about 14 KB. No new frame buffer: the PICA target is already 240x400. The N64 frame copy stays 320x240.
- If a later row widens the frame copy to 400x240: +38 KB per RGBA5551 buffer. Not planned.

## O3DS and N3DS cost (Azahar estimate, not hardware)
- Fill: +25 percent pixels. The PICA fill is not the limit today (PT01: the cost is the CPU GBI walk and the flush).
- Geometry: the wider cull draws more models. Estimate +10 to +25 percent GBI time, about +1 to +4 ms per frame.
- The O3DS can drop more frames to 20 fps in heavy maps with `wide`. The toggle stays available on the O3DS (user decision 1). S28 measures both consoles with `wide pacestat phase`.

## Risks
- BIGGEST: UI and per-scene faults. About 15 PaperBoat patch files, each a place where UI can stretch, shift or cut. F07-3 and F07-5 cover the known list. Unknown sites show only in shots.
- Pop-in at the edges from cull sites other than model.c:2804.
- Frame grabs stay 320x240. A grab shows only the center. The pause blur edges can show a seam.
- Scripted cutscene cameras can show off-stage objects at the sides. PaperBoat has the same limit.
