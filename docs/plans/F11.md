# F11 plan: Options menu (file select item, Select button, settings file)

Status: PLAN ONLY (2026-10-18). No code yet. Row: 3ds/SLICES.md F11. The user decides the open points in "Decisions for the user" before F11-1 starts.

## Verdict
- Difficulty: MEDIUM in total. The first three slices (F11-1 to F11-3) are EASY to MEDIUM. Rebinding (F11-5) is MEDIUM. The "any time" menu (F11-6) is MEDIUM to HARD.
- Pre-S28: F11-1 to F11-3 are easy enough for the pre-S28 list. Azahar can verify all of them. No hardware need.
- Cost of that choice: the S28 gate waits for every open Azahar row. F11 on the pre-S28 list delays S28 by about 3 slices.
- The 60 fps and widescreen toggles do nothing until F06 and F07 (after S28 and optimization). Before that they only store a value. The debug toggles and the settings file have value at once.
- Recommendation: put F11-1 to F11-3 on the pre-S28 list only if the user wants the debug toggles before S28. Else keep F11 with F06 and F07.

## Design

### (a) The file select item
- Add a fourth row (row 3) under Delete, Copy and Cancel. It holds one centered window "Options".
- Room: grow WIN_FILES_MAIN height from 192 to 212 under TARGET_3DS (y 24 to 236, inside 240). Put the new window at y 191, height 16, width 88, centered with `CENTER_WINDOW_X` as WIN_FILES_OPTION_CENTER is (filemenu_main.c:903-904).
- Alternative if the user does not want the frame taller: move WIN_FILES_MAIN up to y 14. The user picks one (decision D1).
- Window id: grow `gWindows`, `gWindowStyles` and the extern in include/variables.h from 64 to 66 under TARGET_3DS. Add WIN_FILES_OPTIONS_ITEM = 64 and WIN_FILES_OPTIONS_PANEL = 65 to include/enums.h under TARGET_3DS. Grep every `64` use with gWindows first (src/bss/engine2_post_bss.c:21 has a second definition, not in the build list. Check it).
- Grid: `numRows` 3 to 4 and one more grid row per state under TARGET_3DS. New value FM_MAIN_OPT_OPTIONS = 7 (after CANCEL). In states other than FM_MAIN_SELECT_FILE, row 3 maps to the row 2 value, so the cursor never lands on Options there. In FM_MAIN_SELECT_FILE, row 3 forces col 1 (same pattern as lines 974-976).
- Draw: a new callback `filemenu_draw_contents_option_options`, a copy of the center callback pattern: `filemenu_set_cursor_goal_pos` when row 3 is selected, then `filemenu_draw_message(filemenu_get_menu_message(FILE_MESSAGE_OPTIONS), ...)`. Show it only in FM_MAIN_SELECT_FILE. Hide it with the other bottom windows in the Delete, Copy, Cancel and file paths (`filemenu_update_hidden_options_bottom`, `filemenu_update_hidden_with_rotation`).
- A on Options: `sfx_play_sound(SOUND_MENU_NEXT)`, set `filemenu_currentMenu = FILE_MENU_OPTIONS`, show WIN_FILES_OPTIONS_PANEL.
- Strings: new US byte arrays in filemenu_msg.c under TARGET_3DS, new enum values after FILE_MESSAGE_PERIOD_34. Text: "Options", "60 FPS", "Widescreen", "On", "Off", "Debug", "Back", one label per debug toggle, "Controls" (later). These are new data, not a stand-in for decomp code.

### The Options panel
- A new MenuPanel `filemenu_options_menuBP` in a new decomp-tree file src/filemenu/filemenu_options.c (TARGET_3DS only, listed in 3ds/CMakeLists.txt). It follows the `filemenu_info_menuBP` and `filemenu_yesno_menuBP` shape: fpInit, fpHandleInput, fpUpdate, fpCleanup, a MenuWindowBP list and draw callbacks.
- Index: FILE_MENU_OPTIONS = 4 on the US build (slot 4 is PAL only and empty on US). `filemenu_menus[]` gets the entry under TARGET_3DS. Do not leave a nullptr hole: the menu loops call fpInit on each entry.
- Contents: one column of rows. Each row is a label and an On or Off value. Up and Down move the cursor (`filemenu_set_cursor_goal_pos`). A or Left and Right flip the value. B or "Back" closes the panel and returns to FILE_MENU_MAIN with the main windows shown again (the Cancel path of `filemenu_info` shows how).
- On or Off display: text "On" and "Off" in the first slice. The Stereo and Mono HES icons are text pictures of those words, so they do not fit other labels.
- The panel reads and writes only `pm_opt` (below) through port functions. It holds no setting logic.

### (b) The Select button
- Read: `pm_pad_scan` reads KEY_SELECT into a port flag `pm_select_edge` (a press since the last game read). Do not map Select to an N64 bit. The N64 pad has no free bit that the game is sure to ignore.
- Padscript: add the token `SELECT` that sets the same flag, so a test can press it.
- First slices: file select only. `filemenu_main_handle_input` calls `pm_pad_take_select()` (TARGET_3DS) in FM_MAIN_SELECT_FILE. A true result opens the panel as A on Options does.
- Any time (F11-6, later): the file menu windows cannot run outside GAME_MODE_FILE_SELECT. Their ids 44 to 63 overlap the pause windows, and the panel would need the file menu update loop. So the "any time" menu must be a port-layer menu: a text menu on the bottom screen console (pm_gpu.c), opened by Select in any game mode. While it is open, `pm_pad_scan` gives the game no buttons and no stick, and the log writer does not print on the bottom screen. This is a port-layer menu with no game logic. It is allowed. It reads the same `pm_opt` table and the same label list.
- Decision D2 for the user: file select only, or also any time (F11-6).

### (c) Contents and data model
Settings struct (3ds/src/pm_options.c, header in 3ds/include/pm_port.h):
- `pm_opt.fps60` (0 or 1). Read by F06 later. No effect before F06.
- `pm_opt.wide` (0 or 1). Read by F07 later. No effect before F07.
- `pm_opt.dbg_hud` (0 or 1): the bottom screen FPS line (pm_main.c:344-353 calls `pm_gpu_hud`).
- `pm_opt.dbg_stats` (0 or 1): the GBI stats line, now the `stats` debug word (pm_main.c:349).
- More debug toggles only for words that the code reads each frame (for example `nofog`, `nolight`, `logstat`). Words that the code reads once at boot (for example `freshsave`, `padscript`, `warp`) stay in debug3ds.txt only. Implement a runtime debug toggle as one more word in the switch string (`pm_log_set_switches`), so every `pm_debug_has` call sees it with no other change.
- `pm_opt.map[N]` (rebind, F11-5): one entry per 3DS input, N = 18 (A, B, X, Y, L, R, ZL, ZR, START, SELECT, D-pad x4, C-stick x4). Each entry is an N64 button mask (u16). Default = the C4E map in pm_input.c:101-114. `pm_pad_scan` then uses one loop over the table for held and edge, in place of the two if-chains. SELECT stays reserved for the menu and is not rebindable. The circle pad stays the N64 stick.

Settings file:
- Path: sdmc:/3ds/PaperMario/options.txt (the working folder). Not in save.flash. The N64 save format does not change.
- Format: text, one `key=value` per line, first line `version=1`. Example: `fps60=0`, `wide=0`, `hud=1`, `map.A=A`, `map.X=CUP`. The user can edit it on a PC.
- Read: once at boot, before `boot_main` (pm_main.c:390). A missing file gives the defaults. An unknown key or a bad value is skipped and logged with one line. The values from debug3ds.txt still apply on top (debug words win, so tests stay the same).
- Write: only when the panel closes and a value changed. Write options.tmp, then rename it to options.txt, so a power loss cannot leave a half file.

## Risks
- Text strings (US ROM): the strings are source data, not ROM data, so no ROM change. The risk is glyph width: the US charset is proportional. "Widescreen" is the longest label. Check that it fits the panel width in the F11-2 shot. Do not add characters outside ASCII letters, digits, space and '.'.
- Save file: options.txt is separate from save.flash. The N64 save does not change. The game's own Stereo and Mono choice stays in the game save as before. Risk: a bad options.txt. The reader skips bad lines and uses defaults.
- Window count: gWindows from 64 to 66 changes BSS by 2 windows (a few hundred bytes). Any code that assumes 64 without ARRAY_COUNT breaks. Grep for `64` near gWindows and gWindowStyles in src/ before F11-2.
- Main window height: a taller WIN_FILES_MAIN changes the file select frame. The golden `fileselect` reference needs an update. The tour and 4-scene A/B rule applies (file select is in the AGENT_RULES list).
- The file menu also opens in game to save (FILE_MESSAGE_SELECT_FILE_TO_SAVE). Show Options only in FM_MAIN_SELECT_FILE at the start of the game, not in the save menu. Check the save path in the F11-2 test.
- Input: Select is not an N64 button. Keep it in a port flag so no game code sees it. For F11-5, a bad map can lock the user out (no A). Keep START and the circle pad fixed, and add the "Reset" row.
- Hardware: SD writes on hardware are slower than on Azahar. Write only on close. The rename step is necessary on FAT. O3DS and N3DS both have Select, so no model difference. ZL, ZR and the C-stick exist only on the N3DS (rebind rows for them do nothing on the O3DS).
- Lane conflicts: F11-2 edits filemenu files that no other open row edits. F11-1 and F11-3 edit pm_main.c and pm_input.c, which C4E-type rows also edit. Run them one at a time.

## Decisions made by the user (2026-10-19)
- D4 = choice A: four debug rows in the panel (HUD, Stats, No fog, No light). Done in F11-3. Rows for Logging and Log level are added by F11-8 below.
- D5 = choice A: F11-5 rebinding covers all 18 inputs.
- C-O3DS: on the O3DS (no ZL, ZR) R plus the Z key gives N64 R and L plus the Z key gives N64 L. The orchestrator left the Z key to the agent. Choice: X. X is the only face key that has a second binding already (D-pad up gives C up as well), so X alone still gives C up and no bind is lost. Held with L or R, X acts as Z key. Y is the alternative (options.txt `o3dsz=1`, Y alone stays C down). L or R alone keep giving N64 Z. N3DS is unchanged. Code: pm_input.c shoulder_map, pm_new3ds from pm_main.c, key o3dsz in options.txt.
- L02 (log levels): pm_log_e, pm_log_w, pm_log_i, pm_log_d. pm_log is info. Switch `loglevel=<0..3 or error, warn, info, debug>`, default warn. Switch `log=off` stops the write to log.txt. run_azahar.ps1 adds `loglevel=debug` to every run, so the tools read all lines.
- F11-8: Options panel rows Logging (On or Off, default On) and Log level (Error, Warn, Info, Debug) in the debug section. They save to options.txt keys `log` and `loglevel` and call pm_log_set_file and pm_log_set_level, the same code as the switches. A switch wins over options.txt. The Fixed seed row (F11-7) goes in the same section later.
