## Part C and the all-functionality rule (user decision 2026-10-18, added to this row)

ALL functionality is ported before S28: game logic, maths, lighting, effects, battles, everything. S28 and later work is hardware compatibility, missed fixes and optimization. No new functionality is ported after S28.

Part C: functionality completeness. The audit must find what is missing or approximated, so faults like the V13 lava texture are caught before S28.
- C1: list every N64 GBI command, RDP mode and RSP feature the game uses (from the decomp and from a display list trace) against what the port handles. Known gaps and approximations to include: fixed light direction for G_LIGHTING, no fog table (F08), no texgen, no LOD, no G_BRANCH_Z, texture tile animation (scroll, pan, tile size), CI palettes, and every render_gaps.md case.
- C2: run all 421 maps, every effect, every battle stage, every actor type and every menu with the unhandled-op counters (the `gbi skip` lines). List every unhandled or approximated path by type and count.
- C3: list stand-ins, shims and approximations in code (grep stub, shim, approximate, TODO, not implemented, unsupported in 3ds/src and in the decomp ifdef paths). Decide each: port it, or prove it holds no game logic.
- C4: compare game logic and maths paths with the decomp for anything the port replaced (audio, math wrappers, RNG, timers, save).
Every finding becomes a fix row, done before S28. Doc edits only.
