Invalidation: pm_tex_invalidate on every ROM read (pm_os.c:317), on decode_yay0 (pm_map.c:375), on the Z buffer and framebuffer (pm_main.c:188, 221), and on a TLUT draw to cimg (pm_gbi.c:1400). ## Class 3: compiler differences

Flags now: -O2 -fsigned-char -fno-strict-aliasing -fwrapv -ffunction-sections -fdata-sections. -fno-short-enums on all game and port files except those that include libctru (PM_NO_SHORT_ENUM_SRC). Game code: `-w` (all warnings off).
- Present and right: -fwrapv, -fno-strict-aliasing, -fno-short-enums, -fsigned-char.
- Missing: -fno-delete-null-pointer-checks and -fno-aggressive-loop-optimizations (the decomp has loops and dereferences written for old GCC). -Wuninitialized is off because of -w. Row: H06a3.
- Float to int casts: ARM saturates at s32 and u32, MIPS wraps. u8 and u16 casts convert through s32 and wrap alike. A grep for float casts to u8, u16, u32 found 6 sites (snd_interface.c:825, msg_draw.c:609, perspective.c:32, hos_05 intro.c:538, osr_03 ending.c:52). All values stay in range. No finding. This is not a proof for every s32 cast.
- Pointer width: both are 32 bit. No bitfields in game structs. 13 u64, s64 uses, none in a shared struct. No sizeof asserts exist (only pm_gpu.c Vert).
- Fixed addresses: pm_gbi.c is_host accepts 0x00100000 to 0x01400000 as host. The 3dsx .bss ends at 0x01394708 (map: .bss 0x00cc45b0 + 0x6d0158). Only 0x6B8F8 bytes (440 KB) remain. F06-2 hit this. Row: H06a2.
- animator.c:84, 347, 1058, 1072 mask pointers with 0xFFFFFF. create_mesh_animator gets render scripts in .data (ends at 0x00CC4594, below 0x01000000). OK now. It breaks if .data passes 16 MB.

## Extension 2026-10-19

(a) ROM addresses. 33 files use *_ROM_START symbols and all resolve at link. Hard-coded: sprite_shading_profiles defsyms 0x315B80 and 0x315D50 in CMakeLists match ver/us/splat.yaml line 1537 and undefined_syms.txt (+0x1D0). pm_map.c ASSET_TABLE 0x1E40020 and SHAPE_BASE 0x80210000 match undefined_syms.txt. No dma_copy with a numeric literal. OK.
(b) Struct size and padding. 32 bit ARM EABI and MIPS o32 agree for u8 to s32, pointers, f32 and f64 (8 byte). No bitfields. No hand-written byte offsets found by grep. Enums fixed by -fno-short-enums. No finding. Endianness of in-place ROM structs is handled by the swap code in pm_map.c, not audited here.
(c) Pointer to integer. All 32 bit. Guards that return silently on a low or high pointer: sprite.c:709, 758, 759 (reject below 0x00100000 or at 0x08000000 and up), 101b90_len_8f0.c:397, 402, npc.c:958. These are port guards inside game code. They hide a fault if hit and break if the sprite heap moves above 0x08000000. Today heap_spriteHead is in .bss, so they pass. Not confirmed, no row.
(d) Buffers sized for N64. gMapShapeData (32 KB to 256 KB), D_80200000 (hud aux, 16 KB to 224 KB) and gBackgroundImage (256 KB, pm_buffers.c) are fixed. Others in heaps.c: D_80204000, D_80207000, D_8020A000 (lava piranha vines, address bases only), BattleEntityHeapBottom 0x3000, gEffectDataBuffer, gEffectGlobals: the game code is the same, so data stays inside the N64 size. The 15 decode_yay0 destinations: most are heap_malloc(decompressedSize) or static arrays sized by the decomp for the real data (jan_04 palette 256, party image, pause palettes 512). battle heap = gFrameBuf2, BATTLE_HEAP_SIZE 0x25800 = FRAME_BUFFER_SIZE. pm_world_entity_heap 0x18000 > WORLD_ENTITY_HEAP_SIZE 0x17FF0. No new finding.
(e) Segments. gSPSegment stores segbase[seg] = ptr_of(w1) (pm_gbi.c:2171). ptr_of tests is_host first, then segbase for seg < 16. Host pointers are at 0x14000000 and up (linear heap) or inside 0x00100000..0x01400000, so a segment word 0x09xxxxxx never matches is_host. VIRTUAL_TO_PHYSICAL is the identity under TARGET_3DS (include/macros.h:68), so effects that pass a host pointer as segment base work. The only risk is the is_host upper bound (H06a2). No other finding.
