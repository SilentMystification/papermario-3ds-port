## Class 2: caches keyed by address

- pm_tex.c Slot cache. Key: img pointer, tlut pointer, fmt, siz, size, palette hash (V06), dkey. It has no content hash of the texels. - pm_gbi.c dec[128] (combiner decision): key is a hash of the combine words, not an address. Collision only. OK.

- pm_gbi.c ldrec, blk, m1, tlut_pal, segbase: per frame draw state, not caches. segbase is set by G_MOVEWORD each use. OK.
- pm_mapdata.c pr[]: keyed by map id. OK.
- pm_tex.c offt: reset by pm_tex_clear_offscreen. OK.
No confirmed finding.

## Class 3: compiler differences

Flags now: -O2 -fsigned-char -fno-strict-aliasing -fwrapv -ffunction-sections -fdata-sections. -fno-short-enums on all game and port files except those that include libctru (PM_NO_SHORT_ENUM_SRC). Game code: `-w` (all warnings off).
- Present and right: -fwrapv, -fno-strict-aliasing, -fno-short-enums, -fsigned-char.
- Missing: -fno-delete-null-pointer-checks and -fno-aggressive-loop-optimizations (the decomp has loops and dereferences written for old GCC). -Wuninitialized is off because of -w. Row: H06a3.
- Float to int casts: ARM saturates at s32 and u32, MIPS wraps. u8 and u16 casts convert through s32 and wrap alike. A grep for float casts to u8, u16, u32 found 6 sites (snd_interface.c:825, msg_draw.c:609, perspective.c:32, hos_05 intro.c:538, osr_03 ending.c:52). All values stay in range. No finding. This is not a proof for every s32 cast.
- Pointer width: both are 32 bit. No bitfields in game structs. 13 u64, s64 uses, none in a shared struct. No sizeof asserts exist (only pm_gpu.c Vert).
- Fixed addresses: pm_gbi.c is_host accepts 0x00100000 to 0x01400000 as host. The 3dsx .bss ends at 0x01394708 (map: .bss 0x00cc45b0 + 0x6d0158). Only 0x6B8F8 bytes (440 KB) remain. F06-2 hit this. Row: H06a2.
- animator.c:84, 347, 1058, 1072 mask pointers with 0xFFFFFF. create_mesh_animator gets render scripts in .data (ends at 0x00CC4594, below 0x01000000). OK now. It breaks if .data passes 16 MB.

## Optimization risks 2026-10-20
Scope: which findings of this audit can break PO2/PO3 (vertex transform on the GPU), MA1 (ARM11 math) or AU1 (audio on core 1). Line numbers are from the working tree of 2026-10-20 (pm_gbi.c has uncommitted edits by another agent).

### PO3 and PO2: vertex transform on the GPU
- Cause 1, per-address caches (class 2). The texture cache has no hash of the texels (pm_tex.c, key list in class 2). A GPU path that keeps converted vertex buffers keyed by the Vtx address has the same fault. Game code writes Vtx fields at run time in these files (count of lines that match a write to `.v.ob`, `.v.tc` or `.v.cn`): src/draw_box.c 100, src/imgfx.c 68, src/msg_draw.c 26, src/hud_element.c 20, src/sprite.c 14, src/effects/whirlwind.c 10, src/effects/water_block.c 9, src/world/area_pra/pra_29/bridge.c 5, src/model.c 5, src/world/area_mac/mac_01/npc/rowf_and_rhuff.inc.c 4, flo_14 bubbles.c 3 (two copies), src/battle/common/stage/lib/Snowflakes.inc.c 3, src/battle/common/stage/area_hos/hos_01.inc.c 3, src/animator.c 3, src/world/common/atomic/WhaleAnim.inc.c 2, src/world/area_hos/hos_03/model_fx.c 1. Rule for PO3: do not cache a vertex buffer by Vtx address. Upload at G_VTX, or key by address plus a content hash.
- Cause 2, vertex buffer rules that the port set by hand. pm_gbi.c:218 vert_live, pm_gbi.c:221 tri_since_vtx (a load at slot 0 starts a new mesh only after a triangle) and pm_gbi.c:1706 to 1750 (G_VTX copy and transform) differ from the real RSP buffer. A GPU path that builds one index buffer per G_VTX must keep the rule of FX3f (aura loads slots 2 and 6, then 0 and 4, then draws 4 to 7). Cross-load references are legal on the RSP. Class 1 (ROM adjacency) is not the same fault, but the V22 scan (docs/plans/dlist_noend.md) only checks the index against the array end. It does not check that a triangle uses a slot that the same list loaded.
- Cause 3, G_MODIFYVTX. pm_gbi.c:1761 sets a screen position per vertex (underwater.c, B5). A GPU transform needs a per-vertex override. Plan this before PO3b.
- Cause 4, the 16 byte matrix id. pm_gbi.c:227 po3a hashes `combined` per G_VTX. The matrix of a vertex is fixed at the load (pm_gbi.c:225 comment). Keep this. A GPU path that uses the matrix at the triangle gives wrong pictures where a list changes the matrix between G_VTX and the triangle.
- Cause 5, buffer readers (class 2). Effects that read the Z buffer or the frame buffer (X02, F03, water_splash) are in docs/plans/PO3.md risk R7. This audit adds no new case.
- Cause 6, is_host and segment addresses (class 3, e, H06a2). Done. A GPU path that pushes host pointers to the GPU must use the same `__end__` bound. A vertex pointer above 0x14000000 is a linear-heap address. GPU DMA needs physical addresses. This is a PO3 task, not a fault today.
- Not affected: -fwrapv and -fno-strict-aliasing flags, uninitialized locals (H06a3 to H06a6 fixed all definite cases), EvtScript ends (H06a1 and H06c).

### MA1: ARM11 math
- Flags: no -ffast-math, no -mfpu or -mcpu flag in 3ds/CMakeLists.txt (grep found none). Line 9 has -O2 -fsigned-char -fno-strict-aliasing -fwrapv. ARM11 has VFPv2. It has no fused multiply-add. `vmla` rounds twice, as two MIPS instructions do. Rule for MA1: do not add a fused multiply-add or NEON path. N3DS has the same ARM11 core, so no such path exists on either console.
- FPSCR: 3ds/src/pm_main.c:54 to 59 sets flush-to-zero (bit 24) and default NaN (bit 25), round to nearest, no traps. The N64 game runs with denormals handled by the FPU exception path. The result for a denormal differs only in the last bit. Risk is low. Do not change this setting inside MA1 without the state hash (MA1 step 0, switch `statehash=<n>`).
- Float to int casts (class 3): ARM saturates and gives 0 for NaN, MIPS `trunc.w.s` gives 0x7FFFFFFF for NaN and for overflow. The 6 u8, u16 and u32 sites are in range (class 3 above). The audit did not read every `(s32)` cast. Any MA1 change that replaces a table (sin_deg, cos_deg) by `sinf` or `cosf` changes the low bits. Q-MA1-P16 in 3ds/QUESTIONS.md asks for this. The state hash decides.
- Uninitialized locals (H06a3 to H06a6): fixed. A result of MA1 that changes after an optimization flag change (-O3, -funroll) may come from a remaining maybe-uninitialized read. Run `-Wmaybe-uninitialized` again if the hash differs.
- No new finding for MA1.

### AU1: audio on core 1
- ROM read path: pm_os.c:332 skips pm_tex_invalidate on the audio thread (`pm_on_audio`, pm_audio.c:117). Texture cache and audio read path are separate. Done in AU1c. The class 2 invalidation list (pm_map.c:375, pm_main.c:188, 221, pm_gbi.c:1510) is all on core 0. No finding.
- Game state read by audio code: src/audio/sfx_control.c:314, 365, 461, 520, 620, 630 (gGameStatusPtr, gPlayerStatus, gCameras), src/audio/ambience.c:79, src/audio/bgm_control.c:55, 192, 198. All are reads. Safe only while core 0 does not write them. The kick at the entry of nuGfxTaskStart (AU1 plan) is after game logic. pm_gbi_run, pm_interp and pm_gpu must not write gCameras or gPlayerStatus. A grep of 3ds/src/pm_gbi.c, pm_interp.c and pm_gpu.c found no such write. Keep this as a rule for PO3.
- Fixed-address assumptions (class 3, e): audio buffers sit in the 4 MB N64 RAM block and in the linear pool. The ndsp buffers need linear memory. This is done in pm_audio.c. No finding.
- Float state shared between the audio thread and game thread is read after the join. No class of this audit applies.
