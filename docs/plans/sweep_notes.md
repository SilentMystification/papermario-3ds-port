# SWEEP notes: the full sweep (bosses, cutscenes, credits)

## Rule
The full sweep runs ONLY when the user asks for a "full sweep". It is not part of any gate, golden run, milestone or feature test. No agent runs it on its own. Rows: PT34, PT35, PT36.

## Files
- `3ds/sweep/sweep.txt`: data, one item per line: `<name> kind=boss|cut|credits|credits_more [warp=<map>:<entry>] [story=<n|intro|epilogue>] [battle=<formation>:<stage>] [jump=<camera x>] cap=<steps> note=...`. Block 1 bosses and block 2 cutscenes at a map entry are generated by `3ds/tools/sweep_gen.py`. Block 3 cutscenes by hand, block 4 credits.
- `3ds/sweep/boss.txt`: padscript driver of a boss item. The player picks the first menu entry (jump) and then the hammer in turns. The boss turns run by themselves. The script repeats (switch `padloop`).
- `3ds/src/pm_sweep.c` (new): switches `sweep=<name> sweepkind=boss|cut sweepcap=<steps> sweepjump=<x>` (one item) and `sweeplist=@sweep/list.txt` (chain: many items in one boot). It logs `sweep:` lines and ends an item. Hooks in old files: one call in `pm_warp.c` (`pm_sweep_tick` in `pm_warp_tick`), one line in `CMakeLists.txt`, the `padloop` switch in `pm_input.c`.
- `3ds/tools/sweep.py` (runner), `sweep_report.py` (table), `sweep_sheet.py` (contact sheet per item), `sweep_gen.py` (lists from the decomp).
- `3ds/routes/credits.txt`: route for the credits (see Credits).
- Output: `3ds/logs/sweep/<item>/` (git-ignored): `log.txt`, `shots/`, `sheet.png` (6 to 12 thumbnails), `time.txt` (Azahar seconds), `azahar.txt` (memory fault lines), `run.txt`. Table: `3ds/logs/sweep/report.txt`.

## How to run a full sweep (Azahar, Linux)
1. Build the lane or main: `PM_LANE=laneC sh 3ds/build.sh` (3dsx in `build3ds/lane-laneC/`).
2. Run (one Azahar start per item, clean state each time, about 25 to 30 s per item):
```
export PM_ROW=SWEEP PM_BUDGET=200
python3 3ds/tools/sweep.py run all --x build3ds/lane-laneC/pm_3ds.3dsx        # or: bosses | cutscenes | credits | credits_more | <item,item>
python3 3ds/tools/sweep.py report                                              # table and sheets again from the logs
```
`--dry` prints the switch strings. `--force` runs an item again (a finished item is skipped). `--chain` runs the whole selection in ONE start (no shots, no clean state, used for the console). The sweep uses its own budget (PM_BUDGET) because one start per item is its design. The user request is the authority for it.
3. Read `3ds/logs/sweep/report.txt`. Columns: result (ok or FAIL with the reason: crash, unmapped memory access, assert or FAIL line, stuck, nostart), steps, cpu ms per step avg/p95/max, steps over 33.3 ms, texture misses, turns (p = player turns, e = enemy moves, m = player moves), Azahar seconds, thumbnails path. Azahar numbers are host numbers. Only console numbers count.
4. Look at `sheet.png` of each item. Faults go to `3ds/SLICES.md` as rows SW<n> (one line each). The sweep fixes nothing.

## Item rules
- Boss item: warp to mac_00:4 with the story value of the area, then the switch `battle=<formation>:<stage>` starts the battle at scene step 30 (as `battle=` always does). Mario HP and max HP are set to 99 and kept full. The padscript driver attacks. End: the battle ends (`end battle`), 900 steps without a battle state change (`end stuck`), no battle in 600 steps (`end nobattle`) or the cap (1500 steps = 50 s of game time, `end cap`). A good boss item has `pturn` of 2 or more and `eturn` of 1 or more.
- Cutscene item: warp to `<map>:<entry>` with a story value, the switch `autoa` presses A. Cap 1200 steps (40 s of game time, the upper limit). The report lists the mode and map changes of the item in the log (`sweep: <name> mode ... map ...`).
- Fast mode: `fast` and Azahar frame limit 1000 (`-F`). A step costs about 12 ms of Azahar time, so 600 steps take 8 s.

## Credits (PT34)
- Warp command: `warp=end_00:0 story=epilogue` (map end_00, entry 0, story 96). `end_00` is the parade of the credits (partners, Toads, bosses). It ends with `GotoMap end_01` (the float parade). `end_00` does not read the story. The real game comes from `kkj_00` entry 6 (`EVS_Scene_Ending`, `GotoMapSpecial end_00`). Both work as a warp target.
- The parade runs about 9400 steps (310 s) in full. The sweep does not play it in full. The first 910 steps are the Luigi part. The phases of the parade start when the camera x passes `PARADE_PHASE_*` (`src/world/area_end/end_00/end_00.h`). The credits items use `jump=<x>`: when the first phase has started, the sweep moves the camera to x - 25 (the cap counts from there). The game starts the phase by itself. The camera moves 14 units per step (20 times the parade speed), so the phases before x start one after the other and the NPC pool does not overflow (a direct jump gave `assert i < MAX_NPC`). Then the item runs 600 steps (20 s) and the sweep takes the last 20 shots into the sheet. Seven short items (`credits`: partners, toads, caravan, boos, yoshis, bowser, end_01 floats) and five more (`credits_more`).
- Select menu entry "Credits": the orchestrator adds the warp `end_00:0` with story `epilogue` (switch form `warp=end_00:0 story=epilogue`, in options.txt `warp=end_00` with entry 0 and story 96 where the menu sets the story).
- Route: `3ds/routes/credits.txt` (waits 5 minutes, marks `seg_min1` to `seg_min4`). Run: `warp=end_00:0 story=epilogue route=credits phase phasecsv loglevel=debug fixedseed`.

## Console (one push, pulled log)
The console cannot start items one by one without hands. It uses the chain: all items in ONE boot, no shots. Build the list on the PC: `python3 3ds/tools/sweep.py run cutscenes --chain --dry` writes `3ds/logs/sweep/chain/list.txt`. Put it and the driver on the SD card (FTP app on the console, port 5000, as in docs/plans/hw_batch.md section 8.4):
```
export O=<ip>; curl -T 3ds/logs/sweep/chain/list.txt --ftp-create-dirs ftp://$O:5000/3ds/PaperMario/sweep/list.txt; curl -T 3ds/sweep/boss.txt ftp://$O:5000/3ds/PaperMario/sweep/boss.txt
sh 3ds/push_3ds.sh --no-build --ip $O -t 20 fast warp=mac_00:4 story=-107 padscript=@sweep/boss.txt padloop sweeplist=@sweep/list.txt phase phasecsv loglevel=debug fixedseed
```
Wait until the log has `sweep: chain end` (about 30 s per boss, 40 s per cutscene of game time at 30 steps per second). Start the FTP app, pull the log: `python3 -u 3ds/tools/ftppull.py $O o build3ds; mkdir -p 3ds/logs/sweep/hw; cp build3ds/hw_o3ds_log.txt 3ds/logs/sweep/hw/log.txt; python3 3ds/tools/sweep_report.py`. The console numbers count (wall time is paced to 33.3 ms). Run bosses and cutscenes as two lists to keep the log short (the log buffer of the console is limited: `loglevel=debug` and `phasecsv` give 3 lines per step).
