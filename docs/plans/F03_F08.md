## F03 depth read back for `is_point_visible`

### Fault
- The decomp copies one pixel of the N64 z-buffer into `DepthCopyBuffer[id]` (BSS u16[16], src/model.c:1349) with a display list: `gDPLoadTextureTile` from `&nuGfxZBuffer[y*320]`, `gDPSetColorImage(DepthCopyBuffer)`, a 1x1 scissor at x = id, one `gSPTextureRectangle`, then the color image goes back to the screen. The next frame the CPU decodes `DepthCopyBuffer[id]` (exponent 3 bits, mantissa 11 bits, dz 2 bits) and compares it with `outZ * MAX_VIEWPORT_DEPTH` (32704).
- The port has no N64 z-buffer. `nuGfxZBuffer` is NULL until the pause code calls `pm_zbuf_need()`. The tile load reads address `(y*320+x)*2` (hos_05 lamp: `tex ptr 0000fd7e`, y 101, x 127). `DepthCopyBuffer` stays 0. Decoded depth 0 is always nearer than the point, so `is_point_visible` returns false when `depthQueryID >= 0`.
- Only one caller uses a query id: `src/effects/bulb_glow.c:192` (data->depthQueryID). `motion_blur_flame.c:168` passes -1 (no depth query). `is_model_center_visible` (model.c:4353) uses the same buffer and is fixed by the same change.

### Mechanism (recommended): emulate the copy in the GBI layer, keep the decomp code
1. In `G_SETCIMG` the port already stores `cimg`. When `cimg == (void*)DepthCopyBuffer` the next `G_TEXRECT` is a depth query. Do not draw it and do not start an off-screen pass.
2. Pixel to read: from `timg` of the last `G_SETTIMG`: `idx = ((u32)timg - (u32)nuGfxZBuffer) / 2`, `y = idx / 320`, `x = idx % 320`. The x part of the offset comes from the macro (the lamp value above decodes to x 127, y 101). Slice step 1 logs `timg`, the `G_LOADTILE` uls/ult and the texrect s, and confirms that one formula gives the same x and y. Fall back to texrect `s >> 5` for x if they differ. Query id = `sci_x0` (the 1x1 scissor).
3. Read one pixel of the last finished PICA depth buffer. `pm_gpu_begin` runs `C3D_FrameBegin(C3D_FRAME_SYNCDRAW)`, so the GPU is idle while the display list is interpreted. The depth buffer holds frame N. The clear in `pm_gpu_end` runs on the GPU before the next command list. This matches the N64 behaviour that the decomp comment states: "last frame's depth value".
   - Buffer: `target->frameBuf.depthBuf`, GPU_RB_DEPTH24_STENCIL8, 4 bytes per pixel, 8x8 tiled in Morton order. Same layout and same coordinate map as the color read in `pm_gpu_read_frame` (pm_gpu.c:554): `fx = 239 - y`, `fy = 40 + x`, `offset = (((fy>>3)*30 + (fx>>3))*64 + morton) * 4`. Low 24 bits are depth, top 8 bits are stencil.
   - Depth sense: port depth map is `C3D_DepthMap(true, -1, ...)` with GREATER test, near = large. Derived: `z01 = 1 - d24 / 16777215.0f`, and z01 equals `outZ` of model.c (0 near, 1 far). The reference port soh-3ds (`depth_snapshot_3ds.h`) uses the same sense: "PICA uses reversed depth: zero is far; the upper byte is stencil". Step 1 of the slice proves it with a log of d24 for a known point, before the encode is trusted.
4. Encode the value into the N64 format that the decomp decodes. `D = round(z01 * 32704)` (MAX_VIEWPORT_DEPTH). `v = D << 3` (18 bit). Pick the exponent e from the table `DepthFloatLookupTable` in reverse: e0 v < 0x20000, e1 < 0x30000, e2 < 0x38000, e3 < 0x3C000, e4 < 0x3E000, e5 < 0x3F000, e6 < 0x3F800, else e7. `mant = ((v - bias[e]) >> shift[e]) & 0x7FF`. Word = `(e << 13) | (mant << 2)` (dz = 0). Write `DepthCopyBuffer[id]`. Compare the decode of the word with D in a host test (below).
5. The first query of a frame needs no allocation. `nuGfxZBuffer` may stay NULL (base 0 in the index formula). No call of `pm_zbuf_need()` (it allocates 150 KB). If the pause code has allocated it, the base is its address and the same formula holds.

### Files and functions
- New `3ds/src/pm_depth.c` (about 60 lines): `int pm_depth_query(const void* timg, int id)` with the Morton read and the encode. `static inline` encode function in `3ds/include/pm_depth.h` so a host test can include it.
- `3ds/src/pm_gpu.c`: one new function `int pm_gpu_depth_at(int x, int y, unsigned* d24)` at the END of the file (reads `target`, which is static). No edit of an existing function.
- `3ds/src/pm_gbi.c`: in `case G_TEXRECT` / `G_TEXRECTFLIP`, one early branch before `rect_to_image(...)` (X02 adds that call): `if (cimg == (void*)DepthCopyBuffer) { pm_depth_query(timg, sci_x0); break; }` plus `extern u16 DepthCopyBuffer[16];` and a counter log (first 8 queries: id, x, y, d24, encoded word).
- `3ds/CMakeLists.txt`: add `src/pm_depth.c` to the source list (one line).
- No change in src/model.c or src/effects. The decomp code stays real and unchanged. This is not a stub: it implements the RDP behaviour (color image write of a z-buffer pixel) that the port layer cannot give by memory.

### Memory and size
- Code about 1.2 KB. Data 0 bytes (one pixel read per query, at most 16 per frame). Far below the 10 KB limit. 3dsx growth about 1.5 KB.
- Rejected: copy the full depth buffer like soh-3ds (300 KB in the CPU, over the memory rule). Rejected: edit `is_point_visible` to read a float depth (changes decomp logic and both functions).

### A/B check
- Host test (the one runnable self-check): `3ds/tools/test_zenc.c` includes `pm_depth.h`, loops D from 0 to 32704, decodes with the table and asserts `|decode - D| <= 8` (the mantissa step of the far exponent, 1 unit of v>>3 at the finest). Run with gcc, no build of the port.
- Log check: `warp=hos_05:0` (the intro room with the lamp, or the `intro` preset) with `-Turbo -Smoke -FaultStop`, fixed length. `log.txt` has the `F03 query` lines with a changing, non-zero word and has no `tex ptr 0000fd7e` line.
- Drawlog check: `drawlog=<f>:<n>` shows the bulb glow draw (an additive rect) present in the frames where the lamp is in view and absent when a wall hides it. Move the camera or use `padscript` to hide the lamp once.
- Golden: `python 3ds/tools/golden.py intro toad yard battle`. `intro` is expected to differ (glow now drawn). toad, yard, battle must show 0 pixel differences (they have no query). Update the `intro` reference only after one by-eye check of one shot.
- Not covered: hardware depth timing, other `depthQueryID` users (none found in src).

### Risks
- Depth sense and scale: derived from the code, not measured. Step 1 log decides. A wrong sense hides the glow always (same as today). Cost of a wrong guess is one slice iteration.
- 24 bit depth is linear in ndc z. The N64 value was an exponent format. The encode keeps the decode within 8 units of D. The compare in the decomp has no bias. Z-fighting of the bulb with its own fixture may flicker the glow. Look at it in the run.
- Frame lag: the read uses depth of frame N while the decomp reads `DepthCopyBuffer` in frame N+1. The decomp lags one frame already. The port lags one more if the interpreter runs the query before the previous frame is drawn. It does not: `C3D_FrameBegin(SYNCDRAW)` waits for the GPU. Check again if PO2 makes the frame begin asynchronous.
- A frame that is not drawn (pause path) leaves old depth. Harmless.

## F08 fog remainder

### What the decomp does
- Fog is used by entity models and animated models (`RENDER_CLASS_FOG` display lists `Gfx_RM3_*`, model.c:1055 and later): render mode cycle 1 is `G_RM_FOG_SHADE_A` = blender (P = FOG color, A = SHADE alpha, M = IN, B = 1-A), geometry mode has `G_FOG`, cycle type 2.
- Setters: `entity_model.c:342-343` and `:655-656`: `gDPSetFogColor(r,g,b,a)` then `gSPFogPosition(min, max)` from `entity_fog_*`; `animator.c:838-839` from `gAnimModelFog*`. `draw_box.c:439` uses `gDPSetFogColor(0,0,0,darkening)` (the A_FOG constant alpha path, V06 done).
- `gSPFogPosition` is `G_MOVEWORD G_MW_FOG G_MWO_FOG` with `w1 = (fm << 16) | fo`, `fm = 128000/(max-min)`, `fo = (500-min)*256/(max-min)` (gbi.h:2709).
- RSP rule (same in reference/sm64-3ds gfx_pc.c:951 and soh-3ds interpreter.cpp:2056): with `G_FOG` set the vertex alpha is replaced by `clamp(z/w * fm + fo, 0, 255)` (z, w are clip coordinates, w <= 0 gives 1/w = 32767). The combiner then reads this value as SHADE alpha, and the blender uses it as the fog weight.
- Fog map to look at: Forever Forest (`world/area_mim/common/SetForeverForestFog.inc.c`, mim_07, mim_11). Animated models in fog via `animator.c:1004`.

### What the port does now
- `pm_gbi.c` `sync_render` (V06) handles only blender A = A_FOG (constant: fog color alpha), P = FOG or BLEND: `pm_gpu_set_mix(1, rgb | fogalpha)`. A = SHADE (`G_RM_FOG_SHADE_A`, `a == 2`) is not matched, so `pm_gpu_set_mix(0, 0)`. The fog blend never runs for entity and animated models.
- `G_MOVEWORD` ignores index `G_MW_FOG` (logs `gbi ignore moveword index 08`). `xform_vtx` keeps the vertex alpha. About 1.3M draws of the tour have `G_FOG` set (counter `st_fogg`, `fogblend` `st_fogb` in the `comb total` log line).
- `pm_gpu.c` builds the mix stage (line 247-258): `INTERPOLATE(CONSTANT rgb, PREVIOUS, CONSTANT alpha)`.

### Mechanism (recommended): N64-exact per-vertex factor, reuse the V06 mix stage
1. `G_MOVEWORD`: new case for index `G_MW_FOG`: `fog_fm = (s16)(w1 >> 16); fog_fo = (s16)w1;` (two statics).
2. `xform_vtx` (pm_gbi.c:471): after the transform, `if (geom & G_FOG) { float winv = o->w > 0 ? 1/o->w : 32767; float f = o->z * winv * fog_fm + fog_fo; o->a = clamp(f, 0, 255); }`. The color alpha attribute then carries the fog factor, and the existing combiner stages read it as shade alpha (as the RDP does). `lerp_clip` already interpolates `a`. The `geom` bit is read at draw time. The decomp sets `G_FOG` before the vertex load in the same display list. Step 1 of the slice checks this with one log (G_FOG at G_VTX time equals at triangle time).
3. `sync_render`: new match for the blender `p == 3 (FOG), a == 2 (SHADE), mm == 0 (IN), b == 0 (1MA)` in cycle 1: call a new `pm_gpu_set_fogmix(1, fogc)` (rgb only). Keep the V06 branch unchanged.
4. `pm_gpu.c`, new second mix mode `r_fogmix` and one stage after the V06 stage: `INTERPOLATE(CONSTANT rgb = fog color, PREVIOUS, PRIMARY_COLOR alpha)`: `C3D_TexEnvSrc(e, C3D_RGB, GPU_CONSTANT, GPU_PREVIOUS, GPU_PRIMARY_COLOR); C3D_TexEnvOpRgb(e, SRC_COLOR, SRC_COLOR, SRC_ALPHA);`. Alpha channel passes (`REPLACE PREVIOUS`). Guard `env_hi < 6` as the V06 stage does.
5. Debug switch `nofog` (A/B, same pattern as `nomix`).

Alternative (PICA fog LUT, as sm64-3ds `gfx_citro3d_set_fog`): `C3D_FogGasMode(GPU_FOG, GPU_PLAIN_DENSITY, true)`, `C3D_FogColor`, `C3D_FogLutBind` with a ramp LUT built from `fm/fo` (`FogLut_FromArray`, 128 entries, about 1 KB per `fm/fo` pair, cached by pair). It frees the texenv stage and needs no vertex change. It is per fragment on the depth buffer, so it needs the exact depth map from F03 step 1, it leaves vertex alpha at 255 (wrong if a fog class combiner reads SHADE alpha, which the RDP value would change), and it needs a flush at each fog on or off change. Use it only if the stage count is not enough: the `comb total` log shows how many fog-class combiners have 6 stages (the mix stage is then skipped). The slice logs this count first. If the count is not 0, switch to the LUT for those draws.

### Files and functions
- `3ds/src/pm_gbi.c`: statics `fog_fm`, `fog_fo`; `case G_MOVEWORD`; `xform_vtx`; `sync_render` (one more branch next to the V06 mix); `nofog` switch. About 25 lines.
- `3ds/src/pm_gpu.c`: `pm_gpu_set_fogmix` (new, 8 lines, next to `pm_gpu_set_mix` at 846), one stage in the texenv build (about 12 lines, next to the V06 stage at 247), `r_fogmix` reset in the same places as `r_mix`.
- `3ds/include/pm_gpu.h`: one prototype.

### Memory and size
- Code about 0.6 KB. Data 0 (LUT variant: 1 KB per pair, up to 8 pairs = 8 KB, inside the limit). 3dsx growth about 1 KB. No texture or vertex buffer change.

### A/B check
- `nofog` switch gives the old picture. `drawlog` lists the draws with fog: add `fog fm fo` to the existing `ddverb` line (no new switch). `stats` line (`fogmode`, `fogblend` counters) shows `fogblend` rising from the old value (the old value counts blenders that matched `a == 1` only).
- Run: `warp=mim_11:0` (Forever Forest, confirm the entry in `pm_warp.c` before the run) with `-Turbo -Smoke -FaultStop`, shots of two frames with and without `nofog`. One contact sheet at most. Fog colour must fade the far trees and the NPC models toward the fog colour. A fog-free map must give 0 pixel difference.
- Golden: `python 3ds/tools/golden.py toad yard battle title`. All must show 0 differences (no `G_FOG` draws there). If `battle` differs, the cause is an animated model with fog on: check by eye.
- Not covered: fog on hardware. The PICA interpolation of alpha is perspective-correct, the RSP value is screen linear. The difference is small and the same one that sm64-3ds accepts.

### Risks
- Fog class combiners may read SHADE alpha as the object alpha. With the factor in alpha, the port now matches the RDP, so the old picture of those draws changes. Look at `battle` for a change.
- Stage count (above). The V06 mix stage and the new one never apply together (one blender per draw).
- `xform_vtx` is called per triangle vertex. Added cost: one divide only for `G_FOG` draws. Measure in the PO phase, not here.
- The geometry-mode timing note in step 2.

Overlaps and the slice order:
1. X02 first (user queue). F03 follows X02: F03 edits `case G_TEXRECT` in the same lines as X02 (`rect_to_image`) and reads `cimg` rules that X02 changes. F03 adds the new code in new files and at the END of `pm_gpu.c`, so the rebase is one branch line.
2. V06 follow-up next. F08 follows V06: both edit `sync_render` (mix block) and the V06 stage in `pm_gpu.c`. F08 adds a new function `pm_gpu_set_fogmix` and a separate stage block and does not edit `pm_gpu_set_mix`.
3. F03 and F08 do not share a function. They may run in either order after their predecessor. F03 first is better: its step 1 proves the depth sense, which the LUT fallback of F08 needs.
4. Both slices change the graphics layer, so only one build agent runs at a time (ORCHESTRATOR rule). No stub is needed in either slice. If the frame begin becomes asynchronous in PO2, repeat the F03 timing check.
