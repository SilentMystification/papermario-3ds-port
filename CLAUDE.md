# papermario-3ds-port rules

Orchestrator sessions: read docs/handoff/orchestrator_rules.md at the start and after every compaction. Code agents: read your row file (docs/handoff/row_<id>.md) first. These rules apply to everyone. Rules are edited in place, never appended.

1. TESTS: run every test through `python 3ds/tools/bench.py run <bench> --row <row> --why "<text>"` (`list`, `show <bench>`); process in docs/handoff/test_catalog.md. Benches: 3ds/tools/bench_defs.json; scenarios: azt_scenarios.json (a new scenario and its bench in the same commit); results: 3ds/logs/perf/runs.jsonl. Set PM_ROW=<row>. Before each Azahar start, write one line to 3ds/logs/perf/status_<row>.txt: what the run measures, which code path, why no other run answers it.
   - SCOPE: test only what the row can change; the row names its scenes first. No sweeps, catalog runs or statehash/golden.py runs. A full test only at an epic merge, else ask the user.
   - GATES: nd_host, the subject picture, and byte checks only for a change to shared draw code, on at most 2 scenes that use it, against the stored base shots of the merge-base (`bench.py base <bench>`, then `bench.py cmp <bench> --row <row>`, test_catalog A6), not a build-at per row. The orchestrator runs one combined smoke after a batch of merges.
   - PASS: the shot shows the subject; counters at 0 are not a pass. The until-line is a log event of the subject. One quantity per shot; no change in the picture: discard the edit. Two unchanged shots end that edit: the next try names a different code point. Try limit: 2 per named cause.
   - TIME: a test ends within 5 s of its until-line. Every scenario has a cap (most 10-25 s, 45 s max unless the scenario states why). No idle menus.
   - BUDGET: 8 Azahar starts per row, 3 for a diagnostic row. At the cap with gates unrun: report INCOMPLETE, reset once (`powershell -NoProfile -File 3ds/run_azahar.ps1 -ResetBudget <row>`, run inside the row's worktree: each worktree has its own test_budget.csv), continue.
2. BUGS (user, 2026-11-06 and 2026-11-09):
   - INVESTIGATE BY CODE: trace producer, state, draw and frame order to a named file, line and value. A shot only confirms a named cause or is the final gate.
   - USER FAULTS ARE FACT (user, 2026-11-10: "Stop doubting my claims"): a fault the user reports is real. Never run tests to prove it exists. Inspect how the thing draws: read the code from the producer through the draw to the pixel, name each code path that can produce the fault (file, line, value) and fix each one. No debug-log runs to check a premise or find a cause (user, 2026-11-10: "Why are you testing with debug logs? you should be INSPECTING HOW THOSE THINGS DRAW"). An Azahar run is only the gate of a fix (the subject looks right, no crash on that path). No cause found by code: hand back the trace; the orchestrator asks the user for facts.
   - STOP RULE: hand back with your state after 90 minutes or 150 tool calls without a passed gate. A row is never relaunched unchanged.
3. AGENT WORK: grep and read line ranges; write tool output to files in build3ds/out/ of your own worktree (never in build3ds/ or build3ds/wt/ of the main folder: it goes away with the worktree). WAITS: run builds and benches in the foreground (timeout up to 600000 ms); no Monitor or tail loops; stop every background task you start.
4. CODE: commit each finished piece (changed files only). No feature toggles (the new path replaces the old one in the same row), no stubs, no git push, no Claude attribution. Debug tools may stay. Untested code stays on a branch. Follow docs/handoff/hw_guidelines.md (ARM11: hot loops fit the 16 KB L1I/L1D, tight data, no division, no double, sequential access, one flush per split).
5. WORKTREES: one worktree per code agent, build3ds/wt/<row> on branch <row>; PM_LANE=<row> on every build.sh and bench call. No git stash (shared by all worktrees). The orchestrator merges and runs `sh 3ds/tools/wt_gc.sh --apply`.
6. PLATFORM: Windows; repo-relative paths, the .ps1 tools, Git Bash for sh tools. Newest information wins over old docs. build.sh generates 3ds/src/map_restore_table.c and 3ds/ld/map_restore*.ld from 3ds/map_restore.txt before each build (git-ignored, never committed, never restored by hand).
7. UPDATE, DO NOT APPEND: state lives in a few living files edited in place; git history is the log.
   - One handoff per epic, docs/handoff/agent_<epic>.md, STATE block of 10 lines or fewer at the top, overwritten. No agent_<epic>b.md, diag_*.md or dated copies.
   - A finding replaces the stale sentence in its subject file (plan, hw_guidelines.md, frame_budget.md). Wrong or finished text is deleted, not corrected below.
   - A row file is deleted by the commit that completes the row.
   - Numbers go into the bench database, never into prose. runs.jsonl is append-only: no run is ever deleted.
   - A new docs/handoff file only for a new subject (search INDEX.md first), with its INDEX.md line in the same commit.
